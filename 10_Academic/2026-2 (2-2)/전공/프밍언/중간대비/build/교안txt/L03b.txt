Static Semantics (정적 의미론)
§ Nothing to do with meaning
§ Context-free grammars (CFGs) cannot describe all of the
  syntax of programming languages
§ Categories of constructs that are trouble:

    • Indirectly related to the meaning of programs (프로그램의 의미와

Attribute Grammars (속성 문법)
§ Attribute grammars (AGs) have additions to CFGs to carry
  some semantic information on parse tree nodes

§ Primary value of AGs:
    • Static semantics specification (정적 의미론을 명세)
    • Compiler design (static semantics checking) (컴파일 시점에 검사)




Chung-Ang University CSE 22405: Principles of Programming Languages   32
Attribute Grammars: Definition (1/2)
§ Def.: An attribute grammar is a context-free grammar
  G=(S,N,T,P) with the following additions:
    • S: the start symbol (a single nonterminal from N)
    • N: the set of nonterminal symbols (variables)
    • T: the set of terminal symbols (tokens/lexemes)
    • P: the set of productions

    • Associated with each grammar symbol X is a set of attributes A(X)
    • Associated with each grammar rule is a set of semantic functions (의미
      함수) and a possibly empty set of predicate functions (술어함수) over the
      attributes of the symbols in the grammar rule.
    • A predicate function has the form of a Boolean expression on the union of
      the attribute set {A(X0),..., A(Xn)} and a set of literal attribute
      values
    • The parse tree is fully attributed if all the attribute values are computed

Attribute Grammars: Definition (2/2)
§ Let "! → "" … "# be a rule
§ Functions of the form & "! = ((* "" , … , * "# ) define
  synthesized (합성) attributes
§ Functions of the form - "$ = ((* "! , … , * "# ), for . ≤ 0 ≤
  1, define inherited (상속) attributes
§ Initially, there are intrinsic (내장) attributes on the leaves
§ A predicate function has the form of a Boolean expression on
  the union of the attribute set {* "! , … , *("# )} and a set of
  literal attribute values

Attribute Grammars: An Example (2/2)
§ Syntax rule
    <expr> → <var>[1] + <var>[2]
    • Semantic rules:
      <expr>.actual_type ← <var>[1].actual_type
    • Predicate:
      <var>[1].actual_type == <var>[2].actual_type
      <expr>.expected_type == <expr>.actual_type

§ Syntax rule
    <var> → A | B | C
    • Semantic rule:
      <var>.actual_type ← lookup (<var>.string)
      - The look-up function looks up a given variable name in the symbol table and
        returns the variable’s type

Semantics (동적 의미론)
§ Meaning of the expressions, statements, and program units
  of a programming language (execution rules)
§ There is no single widely acceptable notation or formalism
  for describing semantics
§ Several needs for a methodology and notation for semantics:
    • Programmers need to know what statements mean
    • Compiler writers must know exactly what language constructs do
    • Correctness proofs would be possible (Axiomatic, 공리의미론)
    • Compiler generators would be possible
    • Designers could detect ambiguities and inconsistencies




Chung-Ang University CSE 22405: Principles of Programming Languages    39
Semantics (동적 의미론)
§ Primary Methods
    • Three main mathematical and logical approaches are used

    • Operational Semantics (연산 의미론)
      - Describes the meaning of language constructs by specifying their effects on an
        ideal machine, focusing on the sequence of changes in the machine’s state

    • Denotational Semantics (표기 의미론)
      - Describes meaning by mapping syntactic elements to specific mathematical
        objects (such as recursive functions) that represent their concrete meanings

    • Axiomatic Semantics (공리 의미론)
      - Based on formal logic, it describes meaning by defining axioms and inference
        rules– such as preconditions and postconditions for each statement– to
        mathematically prove a program’s correctness



Chung-Ang University CSE 22405: Principles of Programming Languages                      40
Operational Semantics
§ Operational Semantics (연산 의미론)
    • Describe the meaning of a program by executing its statements on a
      machine, either simulated or actual.
    • The change in the state of the machine (memory, registers, etc.) defines the
      meaning of the statement
    • Depend on programming languages of lower levels, not mathematics
      - The statements of one programming language are described in terms of the
        statements of a lower-level programming language


§ To use operational semantics for a high-level language, a
  virtual machine is needed

Denotational Semantics (표기 의미론)
§ Based on recursive function theory
§ The process of building a denotational specification for a
  language:
    • Define a mathematical object for each language entity
    • Define a function that maps instances of the language entities onto
      instances of the corresponding mathematical objects (denotational)
      - Syntactic domain (구문 정의역)
      - Semantic domain (의미 정의역)

§ The meaning of language constructs are defined by only the
  values of the program's variables

Axiomatic Semantics (공리 의미론)
§ Based on formal logic (predicate calculus, 술어 계산학)
    • Formal logic (형식 논리) provides the symbolic rules to define, reason
      about, and verify program behavior


§ Original purpose: formal program verification
    • Program verification and program semantics specification


§ Hoare Logic
                                                  $ & '


§ Axioms or inference rules are defined for each statement
  type in the language



Chung-Ang University CSE 22405: Principles of Programming Languages        49
Axiomatic Semantics
§ The logic expressions are called assertions (단언 또는 술어)

§ An assertion before a statement (a precondition, 전조건)
  states the relationships and constraints among variables
  that are true at that point in execution

§ An assertion following a statement is a postcondition (후조건)
    Pre-, post form: {P} statement {Q}


§ A weakest precondition (최약 전조건) is the least restrictive
  precondition that will guarantee the postcondition

Program Proof Process
§ The postcondition for the entire program is the desired result
    • Work back through the program to the first statement.
    • If the precondition on the first statement is the same as the program
      specification, the program is correct.


§ Inference rule (추론 규칙)
    • A method of inferring the truth of one assertion on the basis of the values of
      other assertions

                                           S1 ,S2 , …,Sn
                                                  S

Axiomatic Semantics: Assignment
§ An axiom for assignment statements

                                     x=E : Qx→E               x=E {Q}

                                                 P=Qx→E

    • Example: a = b / 2 – 1 {a < 10}
    • Example: x = x + y - 3 {x > 10}



    • A Logical statement (or theorem)
      - A given assignment state with both a pre- and post-conditions
      - If the assignment axiom, when applied to the postcondition and the assignment
        statement, produces the given precondition, the theorem is proved.

Axiomatic Semantics: Logical Pretest Loops
§ An inference rule for logical pretest loops (논리 사전-검사 루프)

      {P} while B do S end {Q}



                                I and B S {I}
                         I while B do S {I and                        not B }



      , where I is the loop invariant(루프 불변자) (the inductive hypothesis)




Chung-Ang University CSE 22405: Principles of Programming Languages             61
Axiomatic Semantics:
§ Characteristics of the loop invariant: I must meet the
  following conditions:
    • P ⇒ I : the loop invariant must be true initially
    • {I and B} S {I} : I is not changed by executing the body of the loop
    • (I and (not B)) ⇒ Q : if I is true and B is false, Q is implied
    • The loop terminates : can be difficult to prove



      wp(stmt, post-cond.) = pre-cond

Loop Invariant
§ The loop invariant I is a weakened version of the loop
  postcondition, and it is also a precondition
§ I must be weak enough to be satisfied prior to the beginning
  of the loop, but when combined with the loop exit condition,
  it must be strong enough to force the truth of the
  postcondition

§ Total/Partial correctness (전체/부분 정확성)
    • With or without proving loop termination

Evaluation of Axiomatic Semantics
§ Developing axioms or inference rules for all of the
  statements in a language is difficult
§ It is a good tool for correctness proofs, and an excellent
  framework for reasoning about programs, but it is not as
  useful for language users and compiler writers

§ BNF and context-free grammars are equivalent meta-

    • Well-suited for describing the syntax of programming languages

§ Three primary methods of semantics description
    • Operation, axiomatic, denotational
