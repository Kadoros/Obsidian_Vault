Characteristics for Readability (1/4)
§ Why readability (판독성) matters?
    • Maintenance was recognized as a major part of the SW life cycle
    • Ease of maintenance is determined largely by the readability
    • A distinct crossover from a focus on machine orientation to a focus on
      human orientation
    • Readability must be considered in the context of the problem domain


§ Overall simplicity (전반적인 단순성)
    • A language with a small number of features and constructs
    • Minimal feature multiplicity (특징 다중성)
      - Have more than one way to accomplish a particular operation
      - e.g., cnt=cnt+1; cnt+=1; cnt++; ++cnt;
    • Minimal operator overloading (연산자 중복)
      - Operator overloading: a single operator symbol has more than one meaning


Chung-Ang University CSE 22405: Principles of Programming Languages                10
Characteristics for Readability (2/4)
§ Orthogonality (직교성)
    • Every possible combination of primitive constructs is legal and meaningful
      to build another control and data structures
    • More orthogonality → Fewer rule exceptions → Higher degree of regularity →
      Easier to learn/read
    • Example of unorthogonal design in C
      - Records(struct) can be returned from functions, but arrays cannot
      - An array element can be any data type except void or a function
    • Example of orthogonal design (the VAX): ADDL oprd_1, oprd_2
      - In VAX, operands can be registers or memory cells
    • Too much orthogonality can also cause problems
      - x := if a > b then a else b fi;
      - x := (if a > b then a := b else b := a fi);

Characteristics for Readability (3/4)
§ Data types (데이터 타입)
    • The presence of adequate facilities (충분한 장치) for defining data types
      and data structures is good for readability
    • Example: No Boolean type in the language
      - timeOut = 1 vs timeOut = false
      - C89 (ANSI C) and C90 (ISO 90) do not have a native Boolean type
         • Must use integers (0 for false, non-zero for true)
      - C99 introduced the stdbool.h header, which defines a Boolean type
         • bool, true, false

Characteristics for Readability (4/4)
§ Syntax design (구문 설계)
    • The syntax, or form, of the elements of a language has a significant effect
      on the readability of programs
    • Examples of syntactic design choices that affect readability
      - Special words (특수어) (e.g., while, for)
    • The method of forming compound statements
      - C and its descendants use braces “{”, “}” to specify compound statements
      - In ADA, use ‘end if’, ‘end loop’, etc.
    • Form and meaning (형식과 의미): semantics should follow directly from
      syntax
      - In C, the meaning of the reserved word (예약어) static depends on the context of
        its appearance
         • If declared inside a function, the variable is created compile time (not created when the
           function is called.)
         • If declared outside all functions, the variable is visible only in the file

Characteristics for Writability (1/2)
§ A measure of how easily a language can be used to create
  programs for a chosen program domain
    • Most of the language characteristics that affect readability also affect
      writability
    • The context of the target problem domain of a language


§ Simplicity and orthogonality (단순성과 직교성)
    • Few constructs, a small number of primitives, a small set of rules for
      combining them
    • Reduce a misuse of some features and a disuse of others
    • Pros and cons
      - Need to learn only a simple set of primitive constructs
      - Due to too much orthogonality, errors in program can go undetected

Characteristics for Writability (2/2)
§ Expressivity (표현력)
    • Using very powerful operators, a great deal of computation can be

    • Provide relatively convenient ways of specifying computations (e.g., in C,
      the notation count++ is more convenient and shorter than count =
      count + 1)

Characteristics for Reliability
§ Reliable if it performs to its specifications under all
  conditions
§ Language features affecting the reliability
    • Type checking (타입 검사)
      - The earlier errors in programs are detected, the less expensive it is to make the
        required repairs
         • Compile-time vs. Run-time
      - Java checks the types of nearly all variables and expressions at compile time
    • Exception handling (예외 처리)
      - Intercept run-time errors and take corrective measures (시정조치)
    • Aliasing (별칭)
      - Presence of two or more distinct referencing methods for the same memory
        location, resulting in reduced reliability
    • Readability and writability (판독성과 작성력)
      - The easier a program is to read or to write, the more likely it is to be correct

§ Well-known computer architecture: Von Neumann (폰 노이만
   구조)

    • Basis for imperative languages

      - Iteration is efficient

Von Neumann Bottleneck
§ The transfer speed of a bus between a computer’s memory
  and its processor usually determines the speed of a
  computer
§ Program instructions often can be executed much faster
  than the speed of the transfer; the transfer speed thus
  results in a bottleneck
§ The bus speed becomes a bottleneck known as the von
  Neumann bottleneck
    • It is the primary limiting factor in the speed of computers

The von Neumann Architecture (2/2)
§ Fetch-execute cycle (on a von Neumann architecture
  computer)

    initialize the program counter
    repeat forever
         fetch the instruction pointed by the counter
         increment the counter
         decode the instruction
         execute the instruction
    end repeat

Language Design Trade-Offs
§ “There are so many important but conflicting criteria, that
  their reconciliation (절충) and satisfaction (만족) is a major
  engineering task.” (Hoare (1973))
    • Reliability vs. cost of execution
      - Example: Java demands all references to array elements be checked for proper
        indexing, which leads to increased execution costs
    • Readability vs. writability
      - Example: APL provides many powerful operators (and a large number of new
        symbols), allowing complex computations to be written in a compact program
        but at the cost of poor readability
    • Writability (flexibility) vs. reliability
      - Example: C++ pointers are powerful and very flexible but are unreliable

§ Design of a programming language requires many
  compromises and trade-offs

Implementation Methods
§ Compilation (컴파일)
    • Programs are translated into machine language; includes JIT systems
    • Use: Large commercial applications
§ Pure Interpretation (순수 해석)
    • Programs are interpreted by another program known as an interpreter
    • Use: Small programs or when efficiency is not an issue
§ Hybrid Implementation Systems (혼합형 구현 시스템)
    • A compromise between compilers and pure interpreters
    • Use: Small and medium systems when efficiency is not the first concern




Chung-Ang University CSE 22405: Principles of Programming Languages            30
Compilation
§ Translate high-level program (source language, 원시 언어) into
  machine code (machine language, 기계어)
§ Slow translation, fast execution
§ Compilation process has several phases:
    • Lexical analysis: converts characters in the source program into lexical
      units
    • Syntax analysis: transforms lexical units into parse trees which represent
      the syntactic structure of program
    • Semantics analysis: generate intermediate code
    • Code generation: machine code is generated

Pure Interpretation
§ No translation
§ Easier implementation of programs (run-time errors can easily
  and immediately be displayed)
§ Slower execution (10 to 100 times slower than compiled
  programs)
§ Often requires more space
§ Now rare for traditional high-level languages
§ Significant comeback with some Web scripting languages
  (e.g., JavaScript, PHP)

Hybrid Implementation Systems
§ A compromise between compilers and pure interpreters
§ A high-level language program is translated to an
  intermediate language that allows easy interpretation
§ Faster than pure interpretation
§ Examples
    • Perl programs are partially compiled to detect errors before interpretation
    • Initial implementations of Java were hybrid; the intermediate form, byte
      code, provides portability to any machine that has a byte code interpreter
      and a run-time system (together, these are called Java Virtual Machine)

Just-in-Time (JIT) Implementation Systems
§ Initially translate programs to an intermediate language
§ Then compile the intermediate language of the subprograms
  into machine code when they are called during execution
§ The machine code version is kept for subsequent calls
§ JIT systems are widely used for Java programs
§ .NET languages are implemented with a JIT system
§ In essence, JIT systems are delayed compilers

Preprocessors (전처리기)
§ Preprocessor macros (instructions) are commonly used to
  specify that code from another file is to be included
§ A preprocessor processes a program immediately before the
  program is compiled to expand embedded preprocessor
  macros
§ A well-known example: C preprocessor
    • #include “myLib.h” copies the contents of “myLib.h” into the
      program at the position of the #include
    • #define max(A, B) ((A) > (B) ? (A) : (B))
