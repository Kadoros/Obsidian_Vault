Grouping in SQL
q What is Grouping?
  ■ Partition non-overlapping subsets (groups) of tuples in a relation
     q   We may want to apply the aggregate functions to groups of tuples in a relation
          § e.g., Find the average salary of employees in each department or the number of employees who work on each project
  ■ Useful when we want to summarize those groups independently
q Grouping Attributes
  ■ Attributes used as the criteria for grouping
     q   Each group consists of the tuples that have the same value for grouping attribute(s)
  ■ Specified by GROUP BY clause

Specifying General Constraints & Actions
q Assertions
  ■ Specifying general constraints that do not fall into any of the built-in constraints
     q i.e., not covered by the key constraint, entity and referential integrity constraints
     q e.g., the salary of an employee must not be greater than the salary of the manager of the department

q Triggers
  ■ Specifying automatic actions to be taken when certain events and conditions occur
     q   e.g., a manager may want to be informed if an employee’s travel expenses exceed a certain limit

Specifying Actions as Triggers
q The CREATE TRIGGER Command
 ■ Specifying the type of action to be taken when certain conditions are satisfied
 ■ Example: SALARY_VIOLATION
    q We want to check whenever an employee’s salary is greater than the salary of his/her direct supervisor
    q Several events can trigger this rule
       § Inserting a new employee tuple, changing an employee’s salary, or changing an employee’s supervisor
    q The action to take is to call an external stored procedure SALARY_VIOLATION

 ■ A trigger is regarded as an ECA (Event, Condition, Action) rule




                                        Triggers can be used in various applications,
  such as (1) maintaining database consistency, (2) monitoring database updates, and (3) updating derived data automatically

                                                                                                                               26
Specifying Actions as Triggers: Event
q Three Components of Triggers: Event
  ■ Update operations explicitly applied to the database
    q   E.g, Inserting a new employee tuple, changing an employee’s salary, or changing an employee’s supervisor
  ■ The events are specified with the keyword BEFORE or AFTER
    q The trigger should be executed before/after the triggering operation is executed
    q All possible events should be considered




                                                                                                            27
Specifying Actions as Triggers: Condition
q Three Components of Triggers: Condition
  ■ Determines whether the action should be executed when a triggering event occurs
    q   Once the triggering event has occurred, an optional condition may be evaluated
  ■ The condition is specified in WHEN clause of the trigger
    q   Only if it evaluates to true, the action will be executed

Specifying Actions as Triggers: Action
q Three Components of Triggers: Action
  ■ The rule action to be executed automatically
  ■ The action is a sequence of SQL statements, or a database transaction, or an
    external program

View Update: Observations
q View Update
  ■ View update is feasible when only one possible update on the base relations can
    accomplish the desired update operation on the view
q Observations
  ■ Case 1: Multiple Tables with Joins
    q   Views defined on multiple tables using joins are generally not updatable
         § Since a query specified on this view can be mapped to more than one update
  ■ Case 2: Grouping and Aggregate Functions
    q   Views defined using grouping and aggregate functions are not updatable
         § Since a query specified on this view does not make sense
  ■ Case 3: Single Table
    q   A view with a single defining table is updatable if the view attributes contain:
         § 1) The primary key of the base relation;
         § 2) All attributes with the NOT NULL constraint that do not have default values (à why?)
