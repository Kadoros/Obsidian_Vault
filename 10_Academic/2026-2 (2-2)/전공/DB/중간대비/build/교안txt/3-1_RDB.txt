Relational Data Model
q What is a Relational Data Model?
  ■ Database design simplifies data representation, making data management efficient
     q   Developed by Ted Codd of IBM in 1970
  ■ Using relations (i.e., tables) to represent data, where each relation consists of
    tuples (i.e., rows) and attributes (i.e., column headers)




                  Example of Relational Databases     Ted Codd of IBM Research in 1970

                                                                                         4
Advantages of Relational Model
q Simplicity
  ■ Using a flat table structure, making it easy to understand and manage

q Data Integrity
  ■ Ensuring the data in the database is valid, consistent, and accurate

q Easy Data Manipulation
  ■ Supporting powerful, high-level data manipulation languages (i.e., SQL)
    q   Users can flexibly manipulate data along with complex conditions


q Security
  ■ Offering robust security features,
    q   e.g., user authentication, authorization mechanisms, data encryption, and so on

Characteristics of Relations
q Values in Tuples
  ■ Each value in a tuple should be an atomic value
    q   i.e., it is not divisible into components
  ■ Composite and multivalued attributes are NOT allowed
    q Multivalued attributes must be represented by separate relations
    q Composite attributes are represented only by their simple component attributes

q NULLs in Tuples
  ■ NULL values are used to represent the values of attributes that may be unknown or
    may not apply to a tuple
    q   Several meanings for NULL values: unknown, unavailable, undefined values, …

Relational Model Constraints
q What are the Relational Model Constraints?
  ■ Specific constraints that must hold for the data
     q There exit many relations, and their tuples are related in various way
     q For data integrity, every relation database state should follow all the constraints (i.e., valid state)

  ■ DBMS should provide capabilities for defining and enforcing these constraints


q Three Crucial Constraints
  ■ Key Constraints
  ■ Entity integrity Constraints
  ■ Referential integrity Constraints

Key Constraints
q What is a Key Constraint?
  ■ “Two distinct tuples cannot have the identical values for the attributes in SK”
     q   For any two distinct tuples 6" and 6# in a relation state r: 6" SK ≠ 6# SK
  ■ Superkey (SK) of Relational Schema R
     q A subset of attributes in R that can uniquely identifies each tuple
     q Every relation has at least one default superkey

q Why Key Constraints Required?
  ■ In a relation, tuples must be distinct by the definition
  ■ How can we identify each tuple uniquely?

Key Constraints (Cont.)
q Key of Relational Schema R
  ■ A superkey of R with the following additional property
    q   Removing any attribute A from K leaves a set of attributes K’ that is not a superkey of R any more
  ■ It is a minimal superkey
    q We cannot remove any attributes, the uniqueness constraint holds
    q This minimality property is required for a key but optional for a superkey

Operations of Relational Model
q Two Types of Operations
  ■ Retrieval: to retrieve information from the database
  ■ Update: to change the states of relations in the database

q Basic Update Operations
  ■ Insert: insert one or more new tuples into a relation
  ■ Delete: remove tuples from a relation
  ■ Update (or Modify): change attribute values in existing tuples




                    Whenever these operations are applied, some constraints may be violated

Process 1: Regular Entity Types
q Mapping a Regular Entity Type
  ■ (1) Create a relation R that includes all the simple attributes of the entity type E
     q   For a composite attribute, include only the simple component attributes of the composite attribute
  ■ (2) Designate one of the key attributes of E as the primary key for R

Process 2: Weak Entity Types
q Mapping a Weak Entity Type
  ■ (1) Create a relation R including all the simple attributes of the weak entity type W
     q   For a composite attribute, include only the simple component attributes of the composite attribute
  ■ (2) Include the primary key of the owner entity type as a foreign key
     q   This takes care of mapping the identifying relationship type of W
  ■ (3) Set the combination of the owner’s PK and the partial key as the primary key

Takeaways: Relational Data Model
q Relational Model Concepts
  ■ Relations, tuples, attributes, domains
  ■ Characteristics of Relations
  ■ Relational database schema and states

q Relational Model Constraints
  ■ Key Constraints
     q   Two distinct tuples cannot have the identical values for the key attributes
  ■ Entity Integrity Constraints
     q   No primary key value can be NULL
  ■ Referential Integrity Constraints
     q   A value of FK in a tuple either has a value of PK for some tuple or is NULL

Takeaways: Relational Data Model (Cont.)
q Basic Update Operations
  ■ Insert: insert one or more new tuples into a relation
  ■ Delete: remove tuples from a relation
  ■ Update (or Modify): change attribute values in existing tuples

q Constraint Violations
  ■ Insert: may violate any of constraints (key, entity integrity, and referential integrity)
  ■ Delete: may violate the referential integrity constraint
  ■ Update: may violate the key and referential integrity constraint
     q   Only updating the attributes of PK or FK can cause the problems
