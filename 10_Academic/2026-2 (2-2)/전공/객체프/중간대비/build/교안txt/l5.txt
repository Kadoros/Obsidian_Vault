                         References
n   call by reference
    double square (double &x) { return x *= x; }
    int bar (void) {
         double foo = 10.0;
         square (foo);
         cout << foo; // prints 100.0
    }


n   In C, this can be written using pointer
    double square (double *x) { return *x *= *x; }
    int bar (void) {
         double foo = 10.0;
         square (&foo);
         printf (%f, foo); /* prints 100.0 */
    }

               Argument Pasing Modes
                  (The Client’s View)
1.   void X::f(T arg)           // pass by value
2.   void X::f(const T arg)     // pass by value
3.   void X::f(T& arg)          // pass by reference
4.   void X::f(const T& arg)    // pass by referene
5.   void X::f(T* argp)         // pass by pointer
6.   void X::f(const T* argp)   // pass by pointer
7.   void X::f(T* const argp)   // pointer is constant
8.   void X::f(const T* const argp)

• X : class name
• T : data type
• Do not ever use pass by reference (without const qualifier) mode for
  read-only parameters
     Selecting correct mode for arguments
n Avoid passing large objects by value
    n   Why?

n   When passing primitive type arguments (or small objects), use
    value arguments
    n   pass-by-value is safer
n   Use const qualifiers for arguments and functions wherever
    possible.
    n   Make the program more robust
n   Don’t pass pointers when you mean to pass objects.
    n  void f (T* object);
    a.  Pointer object can be NULL. But, there is no null reference.
    b.  Passing a reference does not tansfer the ownership of the object
        to the callee.
         Writing memory safe classes
n   Avoid making copies of objects. Copying an object is expensive
     n   Avoid creating new objects. Try to reuse existing objects
     n   Use const reference parameters when appropriate
     n   Use const member functions
     n   Use pointers instead of references as data members.
     n   Avoid storage allocation in the default constructor. Delay it until the
         member is accessed.
     n   Use reference counting wherever possible.


n   Resist tricks in the initial stage
     n   Stick with safety first; make sure no memory leaks exist
     n   Don’t worry about optimization in the early stages of development.
                 Client’s responsibilities
                with classes and functions
1.   understand the purpose of the class. Even if the name of the class indicates
     that if it is what you need, the documentation may suggest otherwise.
2.   Clearly understand what the class implementor expects from you, the client.
     There is a contract between the client and the implementor.
3.   Pay attention to every member function; in particular, const member
     functions-ther are safer
4.   Understand the arguments being passed.
5.   Understand what your responsibility is when pointers and references are
     returned from functions.
6.   If the class documentation and the information in the header file differ, get
     clarification as to which is correct one before using the class
7.   Prefer functions that accept arguments that are pointers and references to
     const. Ther are safer.
8.   Even if the class implementor is your brother, don’t rely on any undocumented
     class details that he might have told you. Stick to the class interface and
     documentation.
9.   Be wary of classes that don’t implement the minimum set of member
     functions

              Copy-On-Write
n Object creation and destruction is expensive
  n If the copy constructor of a large object is

    frequently called, significant time is spent in
    copying and deleting the dynamically allocated
    memory.

n Copy-on-write
  n Allocate new memory only when writing!

  n Otherwise share the data between original and

    newly created object.
  n Keep reference count (use count) variable.
