                 Software Engineering
n Definition
  n    [IEEE Definition] The application of a systematic, disciplined, quantifiable
       approach to the development, operation, and maintenance of software
      , that is, application of engineering to software

  n   [Firtz Bauer] The establishment and use of sound engineering principles in
      order to economically obtain software that is reliable and works efficiently



n Goals
  n produce a correct, efficient, and reliable software

  n minimize the cost of software development and

      maintenance
                       Goals of SE
n Maintainability
   n   the ability to easily make changes, enhancements, or
       improvements.
n Dependability
   n   the ability to rely on the software to function properly when
       needed.
n Efficiency
   n   the ability for software to use computing resources
       effectively (mainly space and time).
n Usability
   n   the ability for the end user to easily and effectively put the
       software to proper use.

           ADT(Abstract Data Type)
n A set of data variables and associated operations that
  are precisely specified independent of any particular
  implementation.

n ADT = data + operations (no implementation)


n In OOP,
   n   We don’t define data for defining procedures,
   n   But we do define procedures necessary for defining data
   n   ADT is a type that combines data and the procedures

                               Object
n   Object is an instance of class

n   Consists of
    n   Internal data
    n   Internal operations
    n   Interface operations

n   Only class methods can access the internal data of an object.

n   Message passing
    n   Request some work to other object through calling a method.
Object Overview
     Information Hiding/Encapsulation
n   Encapsulation conceals the functional details of a class
    from objects that send messages to it.

n   Internal data of an object can be modified only through an
    interface
                    Class vs Object
n   Each object generated by the same class is different objects
    n   When the objects are created, different memory space and address
        are assigned to each object with unique identifier.

n   Objects created by the same class share the class’s methods.

n   An object can be dynamically constructed or destructed in
    memory during run-time.
                        Inheritance
n   A child class (Sub class) inherits attributes and behaviors of
    parent classes (super class).
n   and can define their own attributes and behaviors.

n   The properties (variables,methods) of a child class should be
    mostly similar to the properties of parent classes.

n   Goal : Object (class) Reuse
n   In large SW development, code reuse reduces costs.
n   We can reuse well-defined classes.
n   Related programs can define new classes using inheritance.
                      Polymorphism
n   Allows the same method (message) to different meaning.

n   the ability of objects belonging to different data types to respond
    to method calls of the same name, each one according to an
    appropriate type-specific behavior.
