# 14장. 예상문제 ✏️

> 답은 `> [!success]- 정답` 토글 안에 숨김.

## ⭕❌ OX 문제

**1.** abstract class는 생성자를 가질 수 없다. (   )
> [!success]- 정답
> ❌ — new로 인스턴스화는 못하지만 생성자는 정의 가능하고, subclass 생성자가 chaining으로 호출한다.

**2.** abstract method를 포함하지 않는 abstract class도 만들 수 있다. (   )
> [!success]- 정답
> ⭕ — 가능하며, base class로 쓰인다. 그래도 new는 불가.

**3.** interface의 메소드는 일부만 abstract여도 된다. (   )
> [!success]- 정답
> ❌ — interface의 모든 메소드는 public abstract이다(생략된 형태). (※ 강의 기준)

**4.** 한 클래스는 여러 interface를 implements 할 수 있다. (   )
> [!success]- 정답
> ⭕ — class는 단일 상속이지만 interface는 다중 구현이 가능하다.

**5.** `new int[10] instanceof Object`는 true이다. (   )
> [!success]- 정답
> ⭕ — 배열도 객체다.

## 🔤 빈칸 채우기

**6.** interface의 모든 변수는 ________ ________ ________ 이다.
> [!success]- 정답
> public static final

**7.** 내용이 없는 빈 interface를 ________ interface라 한다.
> [!success]- 정답
> marker (예: Cloneable, Serializable)

**8.** Comparable의 메소드는 `public int ________(Object o)` 이다.
> [!success]- 정답
> compareTo

## 📝 단답·서술형

**9.** abstract class와 interface의 차이를 변수/생성자/메소드 관점에서 비교하시오.
> [!success]- 정답
> abstract class는 변수에 제한이 없고 생성자를 가지며 concrete 메소드도 가질 수 있다(단 new 불가). interface는 모든 변수가 public static final 상수, 생성자가 없고, 모든 메소드가 public abstract이다. 또 class는 단일 상속, interface는 다중 구현이 가능하다.

**10.** 언제 class 상속을, 언제 interface를 쓰는지 기준을 예와 함께 설명하시오.
> [!success]- 정답
> strong relationship(is-a, parent-child)이면 class 상속(예: staff is a person). weak relationship(특성을 가짐)이면 interface(예: 모든 string은 comparable → String implements Comparable). 다중 상속이 필요하면 하나는 superclass, 나머지는 interface로 설계한다.

**11.** wrapper class의 두 가지 특징을 쓰시오.
> [!success]- 정답
> ① no-arg constructor가 없다 ② 인스턴스가 immutable하다(생성 후 내부 값 변경 불가).

## 💻 코드 분석

**12.** 다음이 컴파일/실행 가능한지 판단하시오.
```java
abstract class GeometricObject { public abstract double getArea(); }
GeometricObject g = new GeometricObject();      // (a)
GeometricObject[] arr = new GeometricObject[10]; // (b)
```
> [!success]- 정답
> (a) ❌ — abstract class는 new로 인스턴스 생성 불가. (b) ⭕ — 배열은 참조 칸만 만드는 것이라 data type으로 사용 가능. 단 각 칸엔 concrete subclass 객체를 넣어야 한다.

**13.** Cloneable을 implements하지 않고 clone()을 호출하면?
> [!success]- 정답
> Object의 clone()에서 CloneNotSupportedException이 runtime에 발생한다. cloning을 지원하려면 implements Cloneable 선언 후 clone()을 override(`return super.clone();`)해야 한다.
