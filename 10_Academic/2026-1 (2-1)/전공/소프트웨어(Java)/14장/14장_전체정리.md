# 14장. Abstract Classes and Interfaces — 전체정리

> 13장 상속의 연장선. "**완성하지 않은 틀**"을 만들어 두고 자식이 채우게 하는 두 장치 — **abstract class**와 **interface** — 가 주인공이다. 둘은 닮았지만 목적이 다르고, 그 차이가 시험의 핵심이다. 뒤에 Comparable/Cloneable, wrapper class, BigInteger까지 응용으로 붙는다.

## 1. 왜 필요한가 (배경)

GUI 프로그래밍을 떠올려 보자. 특징이:
- **동일한 패턴의 반복** (버튼마다 비슷한 처리)
- 프로그램 구동이 **시스템에서부터** 유발됨 (예: 마우스 클릭)
- 이미 만들어진 시스템이 내 프로그램의 handler를 **upcall**(거꾸로 호출)

→ 그래서 **기본 틀/규칙을 미리 만들어 두고, 빈 곳만 상황에 맞게 채우는** 기법이 필요하다. 그 빈 곳을 "반드시 채워라"라고 강제하는 게 abstract class/interface다.

### 프로그래머 간의 약속/계약
실제 프로그램은 절대 혼자 못 만든다. 여러 팀이 나뉘어 개발하고 통합하려면, **먼저 interface(서로 지킬 규칙)를 명확히 정하고** 개발을 시작해야 한다. 팀장이 팀원에게 "이 부분은 내가 짜 둘 테니, 이 메소드는 너희가 이 시그니처대로 채워라"라고 지침을 내리는 상황 = **abstract class**의 본질이다.

## 2. Abstract Class

- class 정의의 일부를 **의도적으로 미완성**한 class.
- 일부는 정의해서 상속으로 쓰게 하고, 미완성 부분은 **반드시 완성해서 쓰라**는 의미를 담는다.
- 대개 **abstract method**(body 없이 signature만 있는 메소드)를 포함한다.
- 즉 그 자체로 쓰는 게 아니라 **base class(틀)** 역할.

```java
public abstract class GeometricObject {
  public abstract double getArea();   // body 없음, signature만 — 자식이 채워라
}
```

### 규칙 정리 (★★ 시험 핵심)
1. **abstract method는 abstract class 안에만** 존재할 수 있다. (일반 class에 abstract method 넣으면 에러.)
2. abstract method가 **하나라도 있으면** 그 class는 **무조건 abstract**여야 한다.
3. abstract class는 **`new`로 인스턴스 생성 불가**: `new GeometricObject()` ❌
   - **그러나 생성자는 정의할 수 있다.** subclass 생성자가 chaining으로 부모(abstract) 생성자를 호출하기 때문. (예: GeometricObject 생성자가 Circle/Rectangle에서 불림.)
4. **abstract method가 없는 abstract class**도 만들 수 있다. 그래도 `new`는 불가, 오직 base class 용도.
5. subclass가 **abstract method를 다 구현하지 않으면** 그 subclass도 **abstract**여야 한다.
6. **superclass가 concrete여도 subclass는 abstract**일 수 있다. (Object는 concrete지만 그 subclass GeometricObject는 abstract.)
7. subclass가 부모의 **concrete method를 abstract로 override**할 수도 있다(드문 경우). 부모 기능을 자식에서 못 쓰게 막을 때.
8. **abstract class를 data type으로는 쓸 수 있다**: 
   ```java
   GeometricObject[] geo = new GeometricObject[10];   // ⭕ 옳다
   ```
   배열은 참조를 담을 칸을 만드는 것일 뿐, abstract class 객체를 만드는 게 아니라서 OK. (각 칸엔 concrete subclass 객체를 넣어야 함.)

## 3. Interface

- **constant와 abstract method만** 포함하는, class 비슷한 construct.
- abstract class와 여러 면에서 닮았지만, **목적이 다르다**: interface의 목적은 객체의 **behavior를 specify(규정)**하는 것.
  - 예: 어떤 객체가 **comparable**(비교 가능), **edible**(먹을 수 있음), **cloneable**(복제 가능)하다고 규칙으로 규정.

```java
public interface Edible {
  public abstract String howToEat();   // 어떻게 먹는지 규정만
}
class Chicken implements Edible {        // implements로 구현
  public String howToEat() { return "Fry it"; }
}
```

### 핵심 성질
- interface는 Java에서 **special class**로 취급 → 별도의 bytecode 파일로 compile된다.
- abstract class처럼 **`new`로 인스턴스 생성 불가**.
- 그러나 **data type으로 사용 가능** — 변수 선언, casting 가능.
- 구현은 **`implements`** 키워드로. (class가 "이 인터페이스를 따른다"고 선언.)
- **Modifier 생략**: interface 안의 모든 data는 `public final static`, 모든 method는 `public abstract`다. 그래서 이 modifier들을 **생략해서 쓴다**.
- 상수 사용: `InterfaceName.CONSTANT_NAME` (예: `T1.K`).

## 4. Comparable Interface

```java
package java.lang;
public interface Comparable {
  public int compareTo(Object o);
}
```
- **String, Date** 등 Java 라이브러리의 많은 클래스가 Comparable을 구현하고 있어 순서 비교가 가능하다.
- `new String() instanceof Comparable` → **true** (String이 Comparable을 implements 하니까).

직접 구현 예 — Rectangle은 Comparable이 없어 크기 비교가 안 되지만, 구현하면 가능:
```java
public class ComparableRectangle extends Rectangle implements Comparable {
  public ComparableRectangle(double w, double h) { super(w, h); }
  public int compareTo(Object o) {
    if (getArea() > ((ComparableRectangle)o).getArea()) return 1;
    else if (getArea() < ((ComparableRectangle)o).getArea()) return -1;
    else return 0;
  }
}
```

### interface가 유용한 이유 (★)
- 어떤 객체 o가 Comparable을 구현한 class의 instance라면, 즉 **`o instanceof Comparable`이 true**라면,
- o는 **`compareTo()`를 반드시 지원한다는 규정을 만족**한다.
- 따라서 Comparable을 요구하는 곳(예: 둘 중 큰 걸 고르는 `Max.max()`)에 **안전하게 넣을 수 있다.**
- 즉 interface는 "이 객체는 이런 능력을 보장한다"는 **계약/보증서** 역할.

## 5. Cloneable Interface (Marker Interface)

```java
public interface Cloneable { }   // 내용이 텅 비어 있음
```
- **Marker interface**: constant도 method도 없는 **빈 interface**. "이 클래스는 이런 성질을 가진다"고 **표시(marker)**만 하는 용도.
- 객체 복제는 안정적 프로그램에 자주 필요하다. Object에 이미 `clone()`이 있지만, 함부로 쓰면 위험(완벽한 복제가 아님)하니, **복제를 허용하겠다고 명시적으로 선언**하게 유도한 것이 Cloneable.
- 정확히는, `clone()`에서 `CloneNotSupportedException`이 나는 걸 방지한다.
- `clone()`은 **protected**라 외부에서 `x.clone()`으로 막 못 쓴다. cloning을 지원하려면:
  1. `implements Cloneable` 선언
  2. `public Object clone() throws CloneNotSupportedException { return super.clone(); }`로 override
- **Shallow vs Deep copy** 차이가 있다(기본 clone은 shallow — 내부 참조는 공유).

## 6. Interface vs Abstract Class (★★ 비교표 — 꼭 외울 것)

| | Variables | Constructors | Methods |
| --- | --- | --- | --- |
| **Abstract class** | 제한 없음 | 있음 (subclass가 chaining으로 호출). **new 불가** | 제한 없음 (**concrete 가능**) |
| **Interface** | **전부 public static final** (상수만) | **없음**. new 불가 | **전부 public abstract** |

추가 차이:
- 모든 class는 **Object라는 하나의 root**를 공유하지만, **interface는 단일 root가 없다.**
- class와 마찬가지로 interface도 **type을 정의**한다. interface 타입 변수는 그걸 구현한 어떤 instance든 참조할 수 있다.
- class는 **단일 상속(extends 하나)**, interface는 **여러 개 구현(implements 여러 개)** 가능.
- **충돌하는 interface**(같은 이름 다른 값 상수, 같은 signature 다른 return type 메소드)는 **컴파일러가 탐지**한다.

### class를 쓸까, interface를 쓸까?
- **strong relationship (is-a, parent-child)** → **class 상속**.
  - 예: staff member **is a** person → 상속으로 모델링.
- **weak relationship (어떤 특성/property를 가짐)** → **interface**.
  - 예: 모든 string은 comparable → String이 Comparable을 구현.
- **다중 상속**이 필요한데 단일 상속 제한에 걸리면 → 하나는 superclass(class), 나머지는 interface로 설계.

## 7. Wrapper Classes

primitive type을 **객체로 감싼** 클래스들: Boolean, Character, Short, Byte, **Integer, Long, Float, Double**.

- 간단한 작업엔 그냥 int/double을 쓰고, **복잡한 작업**(메소드가 필요한)엔 wrapper class를 쓴다.
- 특징 (★ NOTE):
  - **no-arg constructor가 없다.**
  - 인스턴스는 **immutable** — 생성 후 내부 값 변경 불가.
- 각 wrapper는 Object의 `toString`, `equals`, `hashCode`를 override한다.
- numeric wrapper와 Character는 **Comparable을 구현** → `compareTo`가 들어 있다.

### Number class
- numeric wrapper들(Integer, Double …)은 abstract **Number** class를 상속한다.
- 공통 변환 메소드: `doubleValue()`, `floatValue()`, `intValue()`, `longValue()`, `shortValue()`, `byteValue()` — 객체를 해당 primitive 값으로 **convert**.
- 상수: 각 numeric wrapper는 `MAX_VALUE`, `MIN_VALUE`를 가진다.
- 생성/변환:
  ```java
  new Integer(12);  new Integer("12");   // 값 또는 문자열로
  Integer.valueOf("12");                  // static valueOf
  Integer.parseInt("12");                 // 문자열 → int
  Double.parseDouble("12.4");             // 문자열 → double
  ```

### Autoboxing / Unboxing
- JDK 1.5부터 primitive ↔ wrapper **자동 변환**.
  ```java
  Integer[] intArray = {1, 2, 3};                       // autoboxing (int→Integer)
  System.out.println(intArray[0] + intArray[1] + intArray[2]); // unboxing (Integer→int)
  ```

## 8. Generic Sort & Arrays

- Comparable을 구현한 객체 배열은 **generic sort**가 가능하다 (compareTo로 비교).
- `java.util.Arrays.sort(...)`가 표준 제공: `sort(intArray)`, `sort(stringArray)` 등.
- 배열도 객체다: `new int[10] instanceof Object` → true.
- A가 B의 subclass면 `A[]`의 instance는 `B[]`의 instance다. (`new GregorianCalendar[10] instanceof Calendar[]` → true.)
- ⚠️ 단, **primitive 배열은 다르다**: int 값은 double 변수에 넣을 수 있어도, **int[]는 double[]나 Object[]에 대입 불가**.

## 9. BigInteger / BigDecimal

- **매우 큰 수**나 **정교한 소수점** 계산이 필요할 때 (`java.math` 패키지).
- 둘 다 **immutable**, **Number를 상속**, **Comparable을 구현**.
- 연산은 연산자가 아니라 **method로**:
  ```java
  BigInteger a = new BigInteger("9223372036854775807");
  BigInteger c = a.multiply(new BigInteger("2"));      // 곱셈
  BigDecimal d = new BigDecimal(1.0).divide(new BigDecimal(3), 20, BigDecimal.ROUND_UP);
  ```

## 정리 — 이 장의 핵심 한 줄
> abstract class = **미완성 base class**(new 불가, 생성자·concrete 메소드는 가능), interface = **behavior 규정서**(전부 public abstract, 다중 구현). is-a면 class, "특성 보유"면 interface.
