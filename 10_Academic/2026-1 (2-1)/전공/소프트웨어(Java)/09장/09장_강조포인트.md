# 9장. 강조포인트 ⭐

> 슬라이드에서 굵게/빨강으로 짚은 부분 위주

## 🔴 접근 지정자 3종 범위 (제일 기본)
- **public** = 어디서나
- **default** = 같은 package 안에서만
- **private** = 선언된 class 안에서만

## 🔴 객체 변수로 private 접근 불가
- `obj.privateField` → **컴파일 에러**
- 단, **같은 class 내부에서는 접근 가능**
- → 그래서 `main()`을 같은 class에 두는 게 "좋은가?" 라는 질문 자체가 강조 포인트. 답은 **일반 사용 고려해서 getter/setter가 좋다**

## 🔴 Why Data Fields Should Be private? (서술 단골)
1. Data 보호
2. 임의 접근 차단
3. 유지/보수 용이

## 🔴 setter의 검증
```java
radius = (newRadius >= 0) ? newRadius : 0;
```
직접 접근(`obj.radius = -5`)을 막아야 이런 통제가 가능 → private의 진짜 이유

## 🔴 `myCircle.radius` 왜 안 되는가?
- radius가 private이라서. → 반드시 `getRadius()` 통해서.

## 🔴 객체 배열 = 참조 변수 배열
- `new Circle[10]`은 **칸만** 만든다 (전부 null)
- `circleArray[1].getArea()` → **두 단계 참조** (시험에 그림으로 나옴)

## 🔴 Passing reference type
- "the value로 object를 참조한 것이 전달됨" — 참조값이 복사되는 것이지 객체가 복사되는 게 아님

## 🟥 큰 그림
- 결국 **procedure-oriented vs object-oriented**
- 작을 땐 둘 다 OK, **크고 복잡해지면 객체지향이 관리에 유리** (반복 강조)
