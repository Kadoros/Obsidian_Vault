# 18장. 시험노트 📝 (개념 정밀 정리)

## 용어 정의

| 용어 | 정의 |
| --- | --- |
| **exception** | program/외부 환경 때문에 발생, 프로그램이 처리 가능한 error |
| **Error** | JVM이 던지는 internal system error, 거의 복구 불가 |
| **RuntimeException** | 프로그래밍 오류(bad casting, 배열 범위, 숫자 오류) |
| **checked exception** | compiler가 처리를 강요하는 예외 |
| **unchecked exception** | RuntimeException/Error 계열, 강요 안 함 |
| **assertion** | 실행 중 반드시 true여야 하는 Boolean 문장(correctness) |

## 예외 계층
- Throwable → Error / Exception
- Exception → RuntimeException / 그 외(IOException 등)

## Checked vs Unchecked (★★)
- **Unchecked** = RuntimeException, Error + subclass → 처리 강요 X (어디서나 발생 가능해 번잡 방지)
- **Checked** = 나머지 전부 → 반드시 처리
- Catch-or-Declare: checked 던지는 method를 부르면 caller는 (a)try-catch 또는 (b)자신도 throws

## 3대 키워드
- **throws**(선언): `void m() throws IOException`
- **throw**(발생): `throw new TheException();`
- **try-catch**(처리): 여러 catch 가능

## try-catch-finally
- catch는 runtime stack을 따라 내려가며(method 경계 넘어) 탐색
- **finally는 예외 여부와 무관하게 항상 실행**
- rethrow: catch에서 `throw ex;` → finally 후 caller로 제어 이동

## if vs Exception
- exception은 **method 경계를 넘어** 처리 가능, **예상 못 한(unexpected)** 상황 대처 가능
- 단순/예상되는 상황엔 if가 적절 (exception 남용 금지, 자원 더 씀)

## 언제?
- try-catch: 의도치 않은 error condition (예상되는 건 if)
- throw: caller가 처리하길 원할 때. method 안에서 해결되면 throw 안 함

## Custom Exception
- Exception(또는 subclass) 상속
```java
public class InvalidRadiusException extends Exception { ... super("..."); }
```

## Assertion
- `assert 조건 : 메시지;` → false면 **AssertionError**(Error subclass) → 종료
- 기본 **disable**, `java -ea`로 enable
- **Exception=robustness, Assertion=correctness**. assertion은 exception을 대체 못 함
