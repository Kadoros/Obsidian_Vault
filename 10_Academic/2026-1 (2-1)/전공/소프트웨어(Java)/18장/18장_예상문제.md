# 18장. 예상문제 ✏️

> 답은 `> [!success]- 정답` 토글 안에 숨김.

## ⭕❌ OX 문제

**1.** NullPointerException은 checked exception이다. (   )
> [!success]- 정답
> ❌ — RuntimeException 계열이라 unchecked. 처리를 강요하지 않는다.

**2.** finally 블록은 예외가 발생하지 않으면 실행되지 않는다. (   )
> [!success]- 정답
> ❌ — finally는 예외 발생 여부와 관계없이 항상 실행된다.

**3.** checked exception을 던지는 메소드를 호출하면, caller는 try-catch로 잡거나 자신도 throws로 선언해야 한다. (   )
> [!success]- 정답
> ⭕ — Catch-or-Declare 규칙.

**4.** assertion은 exception handling을 대체하기 위한 것이다. (   )
> [!success]- 정답
> ❌ — exception은 robustness, assertion은 correctness용. 서로 대체 불가.

**5.** assertion은 기본적으로 활성화되어 있다. (   )
> [!success]- 정답
> ❌ — 기본 disable. `java -ea`로 켜야 한다.

## 🔤 빈칸 채우기

**6.** 메소드 선언부에서 던질 수 있는 예외를 알리는 키워드는 ________, 실제로 발생시키는 키워드는 ________ 이다.
> [!success]- 정답
> throws / throw

**7.** RuntimeException과 Error 계열을 통틀어 ____________ exception이라 한다.
> [!success]- 정답

**8.** assertion이 false이면 ______________ 가 발생한다.
> [!success]- 정답

## 📝 단답·서술형

**9.** 별도의 예외 처리가 if문 처리보다 나은 점을 설명하시오.
> [!success]- 정답
> ① method 경계를 넘어 caller에게 예외를 전달·처리할 수 있다 ② return value와 별개의 전달 체계를 제공한다 ③ 예상하지 못한(unexpected) 예외 상황까지 대처할 수 있다. 단 단순·예상 상황에는 if가 더 적절하다.

**10.** checked와 unchecked exception의 차이를 설명하시오.
> [!success]- 정답
> compiler가 처리를 강요하느냐의 차이다. RuntimeException과 Error 및 subclass는 unchecked로 강요하지 않는다(어디서나 발생 가능해 try-catch 남발을 피하기 위해). 그 외 exception은 checked로, 반드시 try-catch 하거나 throws로 선언해야 한다.

**11.** Exception과 Assertion의 용도 차이를 쓰시오.
> [!success]- 정답
> Exception handling은 실행 환경을 유지하기 위한 robustness 범주이고, Assertion은 프로그램의 correctness(내부 일관성·타당성)를 확인하기 위한 것이다. assertion은 실행 시 ON/OFF가 가능하며 exception을 대체하지 않는다.

## 💻 코드 분석

**12.** 다음 setRadius의 동작을 설명하시오.
```java
public void setRadius(double newRadius) throws IllegalArgumentException {
  if (newRadius >= 0) radius = newRadius;
  else throw new IllegalArgumentException("Radius cannot be negative");
}
```
> [!success]- 정답
> newRadius가 0 이상이면 정상 대입하고, 음수면 IllegalArgumentException을 생성해 던진다. 이 예외는 이 메소드를 호출한 caller가 try-catch로 처리하게 된다.

**13.** 다음 trace에서 출력 흐름은? (statement2에서 Exception2 발생, catch(Exception2)에 rethrow)
```java
try { s1; s2; s3; }
catch(Exception1 ex){ ... }
catch(Exception2 ex){ handling; throw ex; }
finally { finalStmt; }
Next;
```
> [!success]- 정답
> s1 실행 → s2에서 Exception2 발생(s3 건너뜀) → catch(Exception2)의 handling 실행 → finally의 finalStmt 실행 → rethrow로 예외가 caller로 전달됨. 따라서 Next는 실행되지 않는다.
