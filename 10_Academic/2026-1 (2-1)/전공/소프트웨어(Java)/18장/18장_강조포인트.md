# 18장. 강조포인트 ⭐

## 🔴 Checked vs Unchecked (★★ 1순위)
- **Unchecked** = **RuntimeException + Error** 계열 → compiler가 처리 **강요 안 함**
- **Checked** = 나머지 → 반드시 처리(catch or declare)
- 이유: runtime exception은 어디서나 발생 가능 → 다 강요하면 try-catch 남발

## 🔴 if vs Exception — 왜 따로 배우나
- exception은 **method 경계를 넘어** 처리 가능
- **예상 못 한(unexpected)** 상황까지 대처
- return value와 **별도 전달 체계**

## 🔴 throws / throw / try-catch 구분
- `throws` = 메소드 **선언**부 (이 메소드가 던질 수 있음)
- `throw` = 실제 **발생**시킴 (`throw new ...`)
- `try-catch` = **처리**

## 🔴 finally는 항상 실행 (★)
- 예외가 나든 안 나든 finally 실행
- catch에서 rethrow해도 finally 먼저 실행 후 caller로

## 🔴 Catch-or-Declare
- checked 던지는 method 호출 시 caller는 try-catch 하거나 자기도 throws

## 🔴 Exception vs Assertion
- Exception = **robustness**(실행 환경 유지)
- Assertion = **correctness**(논리 점검)
- assertion이 exception을 **대체 못 함**

## 🔴 Assertion
- `assert 조건 : 메시지;`, 실패 시 **AssertionError**
- 기본 **disable**, `java -ea`로 켬

## 🟥 남용 주의
- 예상되는 단순 상황(예: null 체크)은 **if**로
- exception은 자원을 더 쓴다
