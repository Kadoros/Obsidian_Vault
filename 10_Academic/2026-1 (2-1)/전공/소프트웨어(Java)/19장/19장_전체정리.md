# 19장. Binary (General) I/O — 전체정리

> 파일에 데이터를 읽고 쓰는 장. 핵심 두 가지: ① **text vs binary**의 차이(변환이 있나 없나), ② stream class들을 **양파처럼 감싸서(wrapping)** 원하는 기능을 얹는 구조. 끝에 **객체 저장(Serializable)**과 **임의 접근(RandomAccessFile)**이 응용으로 붙는다.

## 1. 왜 Binary I/O인가

- **Text file**: 사람이 읽을 수 있는 형태(문자의 sequence). text editor로 열린다.
- **Binary file**: binary form. 사람은 해석 못 하고, **program이 해석**하도록 설계된 것.
- 대표 예: Java **source program**은 text file이라 editor로 읽히지만, 컴파일된 **`.class`는 binary file**이라 JVM이 읽는다.
- binary file은 text file보다 **효율적 처리**가 가능하고, **network 통신·device I/O** 프로그래밍에도 필요하다.

## 2. Java의 I/O 처리 방식

- **File 객체**는 file이나 path의 **property만** 가진다 (이름, 존재 여부, 경로 등). 실제 입출력은 안 한다.
- file 입출력을 하려면 **Java I/O class를 쓰는 객체를 따로 생성**해야 한다.
```java
PrintWriter output = new PrintWriter("temp.txt");
output.println("Java 101");
output.close();

Scanner input = new Scanner(new File("temp.txt"));
System.out.println(input.nextLine());
```
→ File은 "파일에 대한 정보", 실제 읽고 쓰기는 stream/Scanner/Writer가 한다는 분리를 기억.

## 3. Text File vs Binary File

- 개략적으로: **text file = 문자의 sequence, binary file = bit(byte)의 sequence.**
- 같은 값 199를 저장하면:
  - **text file**: `'1'`, `'9'`, `'9'` 세 문자의 sequence (3 byte).
  - **binary file**: 10진수 199에 해당하는 16진수 **C7 한 byte**.

## 4. Binary I/O 원리

기본 방식은 Text I/O와 같다(I/O 담당 객체를 만들어 그걸 통해 입출력). **차이는 중간 변환의 유무.**

- **Text I/O**: 중간에 **encoding / decoding**이 일어난다.
  - 출력: unicode → file specific encoded character
  - 입력: file specific encoded character → unicode
- **Binary I/O**: 중간 **conversion이 없다.**
  - 출력: byte in memory → byte in file
  - 입력: byte in file → byte in memory

→ binary는 메모리의 바이트를 그대로 옮기니 빠르고 단순하다.

## 5. Binary I/O Class 계층

### 기반 (base / placeholder)
- **InputStream**: 한 byte를 읽어 **int로 return**.
- **OutputStream**: int로 준 값에 해당하는 **byte를 출력**.
- 이 둘은 실제로 쓰는 I/O class들의 **base class**다. 프로그래머에겐 I/O 객체 생성에 쓰이는 **placeholder** 역할.

### FileInputStream / FileOutputStream
- binary stream과 **file을 결합**한다. 메소드는 모두 superclass에서 상속.
```java
new FileInputStream(String filename);     // 없는 file이면 FileNotFoundException
new FileInputStream(File file);
new FileOutputStream(String filename);
new FileOutputStream(String filename, boolean append);
```
- FileOutputStream: file이 없으면 새로 만들고, 있으면 **append 인자**에 따라 (false)덮어쓰기 / (true)이어쓰기.

### FilterInputStream / FilterOutputStream
- byte를 **걸러서 중간 처리**하는 stream의 base.
- 기본 input stream은 byte를 읽는 `read`만 제공한다. integer·double·string 같은 걸 직접 읽고 싶으면, byte stream에 **처리 코드(filter class)를 감싸야** 한다.

### DataInputStream / DataOutputStream (★)
- **primitive type / string ↔ byte** 변환을 실제로 수행하는 filter.
- DataInputStream: stream에서 byte를 읽어 적절한 primitive 값/string으로 변환 (FilterInputStream 상속, DataInput 구현).
- DataOutputStream: primitive 값/string을 byte로 변환해 stream으로 출력 (FilterOutputStream 상속, DataOutput 구현).

**wrapper 구조** — file stream을 data stream으로 감싼다:
```java
DataInputStream infile =
  new DataInputStream(new FileInputStream("in.dat"));
DataOutputStream outfile =
  new DataOutputStream(new FileOutputStream("out.dat"));
```

#### 문자 / UTF-8
- Unicode는 2 byte. `writeChar(char c)`는 c의 Unicode를, `writeChars(String s)`는 각 문자 Unicode를 쓴다.
- 그런데 8비트 ASCII 문자를 항상 16비트 Unicode로 쓰면 **낭비**다.
- **UTF-8**: ASCII와 Unicode를 효율적으로 표현하는 coding scheme. **1, 2, 또는 3 byte 가변**.
  - ASCII(< 0x7F)는 1 byte, < 0x7FF는 2 byte, 나머지는 3 byte.
  - 웹문서(html, xml)의 표준 저장 형태. `writeUTF()` / `readUTF()`.

#### 주의 (★)
- **EOF 확인**: stream 끝을 넘어 읽으면 `EOFException`. `input.available() == 0`이면 file의 끝.
- **Order & Format**: 읽고 쓸 때 **같은 순서·같은 형식**으로 해야 한다. writeUTF로 썼으면 **readUTF로** 읽어야 함.

### BufferedInputStream / BufferedOutputStream
- **buffer를 써서 I/O 속도를 높인다.**
- 새 method를 추가하지 않고, InputStream/OutputStream의 method를 그대로 상속해 쓴다.
```java
new BufferedInputStream(InputStream in);
new BufferedInputStream(InputStream in, int bufferSize);
```

## 6. Case Study: Copy File

명령줄 인자로 source/target을 받아 복사하는 프로그램.
```
java Copy source target
```
```java
public static void main(String[] args) throws IOException {
  if (args.length != 2) { ... System.exit(0); }
  File sourceFile = new File(args[0]);
  if (!sourceFile.exists()) { /* "not exist" */ System.exit(0); }
  File targetFile = new File(args[1]);
  if (targetFile.exists()) { /* "already exists" */ System.exit(0); }

  BufferedInputStream input  = new BufferedInputStream(new FileInputStream(sourceFile));
  BufferedOutputStream output = new BufferedOutputStream(new FileOutputStream(targetFile));

  int r, numberOfBytesCopied = 0;
  while ((r = input.read()) != -1) {   // 끝이면 -1
    output.write((byte) r);
    numberOfBytesCopied++;
  }
  input.close(); output.close();
  System.out.println(numberOfBytesCopied + " bytes copied");
}
```
- source 없으면 안내, target 이미 있으면 안내(덮어쓰기 방지).
- **버퍼 배열**로 한 번에 여러 byte 읽기(더 빠름):
```java
byte[] buff = new byte[512];
while (input.available() > 0) {
  int n = input.read(buff);
  output.write(buff, 0, n);
  numberOfBytesCopied += n;
}
```

## 7. Object I/O

- DataStream은 primitive/string만 다룬다. **ObjectStream은 객체(object)까지** I/O 가능.
- **ObjectInputStream**(InputStream 상속, ObjectInput·ObjectStreamConstants 구현), **ObjectOutputStream**(OutputStream 상속).
```java
ObjectInputStream  in  = new ObjectInputStream(inputStream);
ObjectOutputStream out = new ObjectOutputStream(outputStream);
out.writeObject(obj);
Object o = in.readObject();
```

### Serializable Interface (★)
- 모든 객체가 stream에 쓰일 수 있는 건 아니다. 쓸 수 있는 객체를 **serializable**하다고 한다.
- serializable하려면 그 객체의 class가 **`java.io.Serializable`을 구현**해야 한다.
- Serializable은 **marker interface** — method가 없어서, 구현해도 추가 코드를 더할 필요가 없다(implements만).
- 구현하면 객체·배열 저장을 자동으로 해 주는 Java **serialization mechanism**이 작동한다.

### transient 키워드
- serializable 객체가 **non-serializable instance field**를 가지면 직렬화될 수 있나? → **No.**
- 그 field에 **`transient`**를 붙이면, 직렬화할 때 JVM이 그 field를 **무시**한다.
```java
public class Foo implements java.io.Serializable {
  private int v1;
  private static double v2;          // static → 직렬화 안 됨
  private transient A v3 = new A();  // transient → 무시
}
class A { }   // A는 non-serializable
```
- 직렬화되는 건 **v1뿐**. v2는 static이라 제외, v3는 transient라 제외. (만약 v3가 transient가 아니었다면 `NotSerializableException` 발생 가능.)

### 배열 직렬화
- 배열은 **모든 element가 serializable일 때** serializable. `writeObject`로 저장하고 나중에 `readObject`로 복원.

## 8. Random Access Files

- 지금까지의 stream은 **read-only 또는 write-only** = **sequential file**(앞에서부터 차례로).
- file을 **수정**하거나 중간에 **새 record를 삽입**할 때는 부적합. → **RandomAccessFile**: file을 **임의 위치(random location)**에서 읽고 쓸 수 있게 해 준다.
```java
RandomAccessFile raf = new RandomAccessFile("test.dat", "rw");  // 읽기+쓰기
RandomAccessFile raf = new RandomAccessFile("test.dat", "r");   // 읽기 전용
```

### File Pointer
- random access file은 byte의 sequence이고, 그 중 한 위치를 가리키는 **file pointer**(특별한 표식)가 있다.
- read/write는 **file pointer 위치에서** 실행되고, 작업 후 pointer가 다음 위치로 이동한다.
  - file을 열면 pointer는 file 시작점.
  - 예: `readInt()`로 int를 읽으면 JVM이 file pointer부터 **4 byte를 읽고 pointer를 4 byte 이동**한다.
- 주요 메소드:
  - `void seek(long pos)` — file 시작점 기준 offset(다음 read/write 위치)을 설정.
  - `long getFilePointer()` — 현재 file pointer offset을 byte로 반환.

## 정리 — 이 장의 핵심 한 줄
> Binary I/O는 **변환 없이 byte↔byte**. file stream을 **Data(형 변환)/Buffered(속도)/Object(객체)** stream으로 **감싸서** 쓴다. 객체 저장은 **Serializable**(transient/static은 제외), 임의 접근은 **RandomAccessFile + file pointer**.
