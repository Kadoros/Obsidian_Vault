## ⭕❌ OX 문제

**1.** superclass의 private member도 subclass에 상속된다. (   )
> [!success]- 정답
> ❌ — private은 상속에서 제외된다.

**2.** static method는 override할 수 있다. (   )
> [!success]- 정답
> ❌ — 상속은 되지만 override 불가. subclass에 같은 static이 있으면 superclass 것은 숨겨진다(hidden).

**3.** `Object o = new Student();`는 명시적 캐스팅이 필요하다. (   )
> [!success]- 정답
> ❌ — up-casting(자식→부모)은 암시적으로 안전하게 된다. 반대로 `Student b = (Student)o;`는 명시적 캐스팅 필요.

**4.** `super(...)` 문장은 생성자 안 어디에 써도 된다. (   )
> [!success]- 정답
> ❌ — 반드시 생성자의 첫 문장이어야 한다.

**5.** 어떤 메소드가 실제로 실행될지는 컴파일 시점에 결정된다. (   )

## 📝 단답·서술형

**9.** down-casting에 명시적 캐스팅을 강요하는 이유를 설명하시오.
> [!success]- 정답
> Object 참조가 실제로 Student를 가리킨다는 보장을 컴파일러가 할 수 없다. 잘못 캐스팅하면 이후 Student 멤버 접근에서 런타임 오류가 난다. 그래서 프로그래머가 의도를 명시할 때만 허용해 오류를 예방한다. (반대로 up-casting은 자식이 부모를 모두 포함하므로 안전해서 암시적)

**10.** constructor chaining을 다음 코드의 출력 순서와 함께 설명하시오.
```java
class Person { Person(){ print("(1)"); } }
class Employee extends Person { Employee(){ this("(2)"); print("(3)"); } Employee(String s){print(s);} }
class Faculty extends Employee { Faculty(){ print("(4)"); } }
new Faculty();
```
> [!success]- 정답
> 출력: (1)(2)(3)(4). new Faculty() → 암시적 super()로 Employee() 호출 → this("(2)")로 Employee(String) 호출하는데 그 전에 super()로 Person() 실행 → (1) → (2) → (3) → 마지막으로 Faculty 본문 (4). 즉 최상위 생성자부터 완료된다.

**11.** Object의 equals()를 override하는 이유와 == 와의 차이를 쓰시오.
> [!success]- 정답
> 기본 equals는 `this==obj`로 참조 동일성만 본다. 두 객체의 내용이 같은지 비교하려면 클래스 의미에 맞게 override해야 한다. ==는 primitive 값 또는 같은 참조인지를 보고, equals는 내용 비교용(재정의 가능)이다.

## 💻 코드 분석

**12.** 아래 코드가 에러인 이유는?
```java
class Fruit { public Fruit(String name) { } }
public class Apple extends Fruit { }
```
> [!success]- 정답
> Apple의 기본 생성자가 암시적으로 `super()`(no-arg)를 호출하려 하는데, Fruit에는 no-arg constructor가 없다(String 받는 것만 있음). 따라서 컴파일 에러. Apple에서 `super(name)`을 명시적으로 호출해야 한다.

**13.** `GenericStack<String> s`에 대해 `s.push(2);`가 에러인 이유는?
> [!success]- 정답
> E가 String으로 고정된 type-safe 스택이라 int 2는 받을 수 없다. parameterized type이 컴파일 시점에 타입 안전성을 보장한다.
