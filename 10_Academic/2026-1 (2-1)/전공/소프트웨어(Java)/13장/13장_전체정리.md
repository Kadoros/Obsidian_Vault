# 13장. 상속 (Inheritance) — 전체정리

> 객체지향의 3대 기둥(캡슐화·상속·다형성) 중 **상속과 다형성**이 한꺼번에 나오는, 사실상 이 과목의 산봉우리다. 상속의 의미 → super/생성자 → overriding → Object class → **다형성/동적바인딩** → casting/instanceof → ArrayList/Generic → protected/final 순서로 차곡차곡 쌓인다.

## 1. 왜 상속인가 (Motivation)

원, 사각형, 삼각형을 모델링한다고 하자. 이들은 **공통 특징**(색, 채움 여부, 넓이/둘레 개념 등)을 공유한다. 매번 새 도형이 필요할 때마다 처음부터 다 새로 정의하면? → **코드 중복**이 폭발한다. 이 중복을 없애는 정답이 **inheritance**다. 공통은 부모에 한 번만 두고, 각 도형은 다른 점만 추가한다.

## 2. Superclass / Subclass

```java
class Circle4 extends GeometricObject1 { ... }
```
- **subclass extends superclass** ("자식이 부모를 확장한다").
- superclass의 속성·method가 subclass에 **상속된다** — **단 private은 제외**.
- subclass는 **고유한 속성·method만 추가**하면 되고, 때로는 자신에게 안 맞는 부분을 **재정의(overriding)**한다.

### inheritance vs (include / import)
이게 진짜 의미 포인트다. 상속은 단순히 "다른 클래스를 갖다 쓰는 것"이 아니다.
- 단순 "사용 가능"이 아니라 **그 멤버가 내 class의 일부분**이 된다 (메소드·멤버 변수가 내 것처럼).
- **재정의(overriding)가 가능**하다.
- 핵심은 **"extends해서 구체화"** — 부모를 가져와 더 구체적으로 만드는 것.

```java
// 상속(O): getColor가 c의 멤버처럼 됨        // 멤버변수로 포함(다른 의미): 한 단계 더 거침
class Circle extends GeometricObject {        class Circle {
   double radius;                               GeometricObject geo = new GeometricObject();
   ...                                          double radius;
}                                             }
Circle c = new Circle();                      Circle c = new Circle();
c.getColor();   // 바로 내 것처럼              c.geo.getColor();  // geo를 거쳐야
```

## 3. extends의 의미 (★ 헷갈림 1순위)

`class A extends B`를 영어로 읽으면 "A가 B를 확장(넓힌다)"이라 **A가 더 넓을 것 같지만, 반대다.**
- 의미는 "A는 B에 **추가 사항을 덧붙여** 정의된다".
- 추가된 기술 → **더 구체적** → **더 좁은 의미!**
- 즉 **A는 특화된(더 구체화된) B**다. 반대로 A는 B로 **일반화**되어 B가 요구되는 자리에 쓰일 수 있다.

```java
class Student extends Person {}        // Student는 Person보다 좁고 구체적
class Staff   extends Person {}
class GradStudent extends Student {}   // 더 좁아짐
```
- 의미적으로 subclass ⊂ superclass (학생들 ⊂ 사람들).
- 코드적으로는 subclass가 superclass 코드를 **포함**한다(상속받아서).
- 집합 관계보다 **상/하 관계(상속 관계)**로 해석하는 게 맞다.

## 4. 생성자와 super

### 상위 객체가 먼저 생성된다
- subclass 생성자에서 superclass 생성자가 **명시적(super) 또는 암시적**으로 호출된다.
- `super`를 안 쓰면 컴파일러가 **superclass의 no-arg constructor를 자동 호출**한다 (첫 줄에 `super()`를 넣어줌).
- 순서: **상위 클래스 객체가 먼저 생성/초기화 → 그 다음 하위.** (집을 지을 때 토대부터.)

### super 키워드 — 두 용도
1. **superclass constructor 호출**: `super(...)`
2. **superclass의 method/변수 접근**: `super.getDateCreated()`

주의사항:
- superclass 생성자를 부르려면 **반드시 `super`**를 쓴다. 생성자 이름을 직접 부르면 **구문 오류**.
- `super(...)` 문장은 **constructor에서 가장 먼저** 나와야 한다 (상위 먼저 초기화하니까).

### Constructor Chaining (★ 그림 단골)
인스턴스를 만들면 상속 사슬을 따라 **모든 상위 생성자가 호출**된다. 이걸 constructor chaining이라 한다.

```java
public class Faculty extends Employee {
  public static void main(String[] args) { new Faculty(); }
  public Faculty() { System.out.println("(4) Faculty's no-arg"); }
}
class Employee extends Person {
  public Employee() {
    this("(2) Employee's overloaded");      // 같은 클래스 다른 생성자
    System.out.println("(3) Employee's no-arg");
  }
  public Employee(String s) { System.out.println(s); }
}
class Person {
  public Person() { System.out.println("(1) Person's no-arg"); }
}
```
**출력 순서: (1)(2)(3)(4).**
흐름: `new Faculty()` → 암시적 `super()`로 Employee() 진입 → Employee()의 `this(...)`가 Employee(String) 호출, 그 전에 또 `super()`로 Person() 실행 → **(1) Person 완료** → **(2) Employee(String)** → **(3) Employee no-arg** → **(4) Faculty**. 즉 **가장 위(Person)부터 완료되며 내려온다.**

### 생성자 없는 Superclass 함정
```java
class Fruit { public Fruit(String name) { ... } }   // no-arg 생성자가 없다!
public class Apple extends Fruit { }                  // ❌ 컴파일 에러
```
Apple의 기본 생성자가 암시적으로 `super()`(no-arg)를 부르려 하는데, Fruit엔 no-arg가 없다(String 받는 것만 있음). → 에러. 해결: Apple에서 `super(name)`을 명시.

## 5. Overriding (재정의)

subclass가 superclass에서 상속한 메소드를, 자신에 맞게 **수정**하는 것.
```java
public class Circle extends GeometricObject {
  /** 부모 toString을 재정의 + 부모 기능 활용 */
  public String toString() {
    return super.toString() + "\nradius is " + radius;
  }
}
```
- `super.toString()`으로 **부모 기능을 활용**하면서 자기 내용을 덧붙일 수 있다.

### Overriding 주의 (★)
- **private method는 override 불가.** 외부에서 접근이 안 되니까. subclass에 같은 이름이 있어도 둘은 **완전히 무관한 별개 메소드**(=메소드 추가).
- **static method는 override 불가.** 상속은 되지만 재정의는 아니다. subclass에 같은 static이 있으면 부모 것은 **숨겨진다(hidden)**.
- **instance method는 superclass의 static method를 override 할 수 없다.**

### Overriding vs Overloading
| | signature | 관계 | 의미 |
| --- | --- | --- | --- |
| **Overriding** | **같음** | 상속(부모-자식) | 재정의 |
| **Overloading** | 다름(인자 수/형) | 같은 class 등 | 추가 정의 |

## 6. Object Class

- 자바의 **모든 class는 java.lang.Object를 상속**한다. 상속을 지정하지 않으면 그 클래스의 superclass는 자동으로 Object.
- 즉 Object는 모든 클래스의 **공통 뿌리(root)**.

### toString()
- 기본 구현은 `클래스이름@16진수` 형태. 예: `Loan@15037e5` (의미 없는 주소값).
- 객체에 맞는 정보를 담도록 **override 하는 게 권장**.

### equals()
- Object의 기본 equals는 **참조 비교**다:
  ```java
  public boolean equals(Object obj) { return (this == obj); }
  ```
- 내용 비교를 원하면 클래스 의미에 맞게 **override**:
  ```java
  public boolean equals(Object o) {
    if (o instanceof Circle) return radius == ((Circle)o).radius;
    else return false;
  }
  ```

### == vs equals() (★)
- **`==`**: primitive 값 비교, 또는 두 객체가 **같은 참조(reference)**인지 검사.
- **`equals()`**: 두 객체의 **내용**이 같은지 검사 (재정의 가능).
- `==`가 더 강하다: 같은 객체를 가리키면 내용도 당연히 같다.

## 7. Polymorphism / Dynamic Binding / Generic Programming

이 셋은 한 묶음이다.

### Polymorphism (다형성)
- `m(Object x)`를 호출할 때, x는 실행 상황에 따라 GraduateStudent, Student, Person, Object 무엇이든 될 수 있다.
- 원리: **subtype의 객체는 supertype이 요구되는 자리에 쓸 수 있다.** (학생은 사람이 필요한 곳에 들어갈 수 있다.)
```java
public static void m(Object x) { System.out.println(x.toString()); }
m(new GraduateStudent()); m(new Student()); m(new Person()); m(new Object());
```

### Dynamic Binding (동적 바인딩)
- 위에서 `x.toString()`이 실행될 때, **어느 클래스의 toString이 실행될지는 runtime에 JVM이 동적으로 결정**한다.
- 원리: 객체 o가 C1, C2, …, Cn(=Object) 사슬일 때(C1이 가장 구체적), JVM은 **C1부터 위로** toString 구현을 찾아 **처음 발견한 것**을 호출한다. Student에 toString이 있으면 그게 불린다.

### Method Matching vs Binding
- **Matching (compile time)**: 컴파일러가 parameter의 형·개수·순서로 **어떤 메소드인지 찾는다**.
- **Binding (runtime)**: JVM이 그 메소드의 **실제 구현을 동적으로 연결**한다.
- 둘은 **별개의 단계**. (찾는 것 ≠ 실행할 구현을 고르는 것.)

### Generic Programming
- 다형성을 이용해 다양한 객체에 두루 쓰이는 일반형 메소드를 짜는 것.
- 형식 인자를 superclass(예 Object)로 두면, 그 subclass 객체들을 다 넘길 수 있다. 호출되는 구현(예 toString)은 동적으로 결정된다.

## 8. Casting (형 변환)

```java
Object o = new Student();   // up-casting (자식→부모): 암시적, 항상 안전
Student b = (Student)o;     // down-casting (부모→자식): 명시적 캐스팅 필요
```
- **up-casting**: 자식은 부모 내용을 다 포함하므로 부모로 다루는 건 늘 안전 → 암시적으로 OK.
- **down-casting**: 부모 참조가 정말 그 자식을 가리키는지 컴파일러가 보장 못 하므로, **명시적 캐스팅으로 프로그래머가 책임진다고 표시**해야 허용.

왜 강요하나? `Object o = new Student(); Student b = o;`에서 `Student b = o`가 컴파일 에러인 이유 — o가 진짜 Student를 가리킨다는 걸 컴파일 타임에 확신할 수 없어서, 잘못된 후속 접근으로 런타임 오류가 날 수 있다. 그래서 `(Student)o`로 의도를 명시할 때만 허용한다.

- 항상 성공하는 건 아니다: `Apple x = (Apple)fruit;`는 fruit이 실제 Apple일 때만. (TIP 비유: apple은 fruit이니 Fruit 변수에 Apple 넣기는 안전, 그러나 fruit이 반드시 apple은 아니니 Apple 변수에 Fruit 넣으려면 명시 캐스팅.)

### instanceof
캐스팅 전에 실제 타입을 확인하는 안전장치.
```java
Object myObject = new Circle();
if (myObject instanceof Circle) {
  System.out.println(((Circle)myObject).getDiameter());
}
```

## 9. ArrayList (와 Vector)

- Object를 저장하는 **크기 가변** 배열. 개념적으로 **Array + (Linked) List**.
- 임의의 크기에, 임의의 객체를, 배열처럼 담아 쓴다.

| 배열 (`Friend[]`) | ArrayList (`ArrayList<Friend>`) |
| --- | --- |
| `Friend[] fl = new Friend[100];` | `ArrayList<Friend> flist = new ArrayList<>();` |
| `f = fl[i];` | `f = flist.get(i);` |
| `fl[i] = f;` | `flist.set(i, f);` / `flist.add(i, f);` |
| `fl.length` | `flist.size()` (실제 원소 수) |
| (직접 검색) | `flist.contains(f)` |

## 10. Generic Programming (Parameterized Type)

`<E>`로 담을 타입을 매개변수화하면 **type-safe**해진다.
```java
public class GenericStack<E> {
  private ArrayList<E> list = new ArrayList<E>();
  public void push(E o) { list.add(o); }
  public E pop() {
    E o = list.get(getSize() - 1);
    list.remove(getSize() - 1);
    return o;
  }
  public int getSize() { return list.size(); }
}

GenericStack<String> s = new GenericStack<>();
s.push("first");   // OK
s.push(2);         // ❌ 컴파일 에러 — String 스택에 int 불가
```
→ 잘못된 타입을 **컴파일 시점에 막아준다**. (이전엔 "unchecked operation" 경고가 났던 부분.)

## 11. protected / final

### protected
- public class의 protected 멤버는 **같은 package의 모든 class** + **다른 package의 subclass**에서 접근 가능.
- 접근 범위 순서: **private < default < protected < public** (좁음 → 넓음).
- ⚠️ subclass는 superclass 메소드의 접근성을 **약화시킬 수 없다.** 부모에서 public이면 자식에서도 public이어야 한다(좁히기 불가, 넓히기는 가능 — protected를 public으로 override는 OK).

### final
- **`final class`** → **상속 불가**. 예: `final class Math`.
- **`final 변수`** → **상수**. 예: `final static double PI = 3.14159;`.
- **`final method`** → subclass에서 **override 불가**.
- final은 class·멤버뿐 아니라 메소드의 **local 변수**에도 쓸 수 있다(local 상수).

## 정리 — 이 장의 핵심 한 줄
> 상속은 **"extends해서 구체화"**(private 제외 상속), 생성은 **상위부터(constructor chaining)**, 실행할 메소드는 **runtime에 동적 결정(dynamic binding)**. 부모↔자식 형변환은 **up은 암시·down은 명시**.
