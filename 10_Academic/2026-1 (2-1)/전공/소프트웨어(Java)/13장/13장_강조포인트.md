# 13장. 강조포인트 ⭐

## 🔴 상속되는 것 / 안 되는 것
- superclass 속성·method 상속 — **단 private 제외**
- 핵심: 단순 사용(include/import)이 아니라 **"extends해서 구체화"**

## 🔴 extends = 더 좁은 의미 (헷갈림 1순위)
- A extends B → A가 **더 구체적, 더 좁음**
- "확장"이라는 단어에 속지 말 것

## 🔴 super (★)
- `super(...)` = 상위 생성자 호출, **반드시 constructor 첫 줄**
- 상위 객체 **먼저** 생성
- super 안 쓰면 no-arg `super()` 자동

## 🔴 Constructor Chaining (그림 단골)
- new 하면 **모든 상위 생성자 호출**
- 출력 순서: **최상위부터** (Person→Employee→Faculty)
- superclass에 no-arg 없으면 → **Error**

## 🔴 override 불가 3종
- **private** (별개 메소드가 됨)
- **static** (상속은 되나 재정의 X, hidden)
- instance가 superclass의 static을 override 불가

## 🔴 == vs equals
- `==` 참조/값 비교 (더 강함), `equals` 내용 비교(override 가능)
- Object 기본 equals는 `this==obj`

## 🔴 Casting
- 자식→부모(up) **암시적/안전**
- 부모→자식(down) **명시적 필수**
- `Object o = new Student()`는 OK, `Student b = o`는 **컴파일 에러** → `(Student)o` 필요
- 왜? 컴파일러가 오류 방지 위해 의도를 강요

## 🔴 Dynamic Binding
- 어떤 메소드 실행할지 **runtime에 JVM이 결정**
- C1(구체)부터 위로 찾아 처음 발견한 구현 호출

## 🔴 GenericStack<E> = type-safe
- `<String>` 스택에 `push(2)` → **error**

## 🟥 protected / final
- 범위 private < default < protected < public
- subclass는 접근성 **약화 못 함**
- final class 상속불가 / final 변수 상수 / final method override 불가
