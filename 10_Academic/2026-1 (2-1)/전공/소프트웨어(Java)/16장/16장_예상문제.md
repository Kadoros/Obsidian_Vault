# 16장. 예상문제 ✏️

> 답은 `> [!success]- 정답` 토글 안에 숨김.

## ⭕❌ OX 문제

**1.** event-driven 프로그램은 코드가 작성된 절차 순서대로만 실행된다. (   )
> [!success]- 정답
> ❌ — event가 활성화될 때 해당 코드가 실행된다. 절차 순서 실행은 procedural programming.

**2.** listener의 handler method는 프로그래머가 직접 호출한다. (   )
> [!success]- 정답
> ❌ — 시스템(JVM)이 event 발생 시 upcall한다. 그래서 정해진 Interface를 implements해야 한다.

**3.** anonymous inner class는 extends/implements 키워드를 쓴다. (   )
> [!success]- 정답
> ❌ — 쓰지 않는다. 선언과 동시에 superclass/interface를 따르되 키워드 없이 작성한다.

**4.** JButton을 클릭하면 ActionEvent가 발생한다. (   )
> [!success]- 정답
> ⭕

## 🔤 빈칸 채우기

**5.** ActionEvent를 처리하는 listener interface는 ____________ 이고, 그 handler method는 ________________ 이다.
> [!success]- 정답
> ActionListener / actionPerformed(ActionEvent)

**6.** event를 발생시킨 객체를 알아내는 메소드는 ____________ 이다.
> [!success]- 정답
> getSource()

**7.** 일정 주기마다 ActionEvent를 발생시켜 애니메이션에 쓰는 클래스는 ________ 이다.
> [!success]- 정답
> javax.swing.Timer

## 📝 단답·서술형

**8.** Java event-driven 프로그래밍의 3단계를 쓰시오.
> [!success]- 정답
> ① 어떤 이벤트인지 명시(Event Source + Event Class) ② 처리 handler를 약속된 Interface대로 구현해 class화 ③ event source에 listener를 등록(addXxxListener)하여 event와 handler를 연결.

**9.** 핸들러를 정해진 interface대로 구현해야 하는 이유를 설명하시오.
> [!success]- 정답
> 핸들러 method는 프로그래머가 아니라 시스템(JVM)이 event 발생 시 upcall한다. JVM이 호출할 수 있으려면 method 이름·시그니처가 약속(interface)대로여야 하므로 반드시 해당 listener interface를 implements해야 한다.

**10.** inner class를 listener로 쓰는 장점 2가지를 쓰시오.
> [!success]- 정답
> ① outer class의 method와 data를 직접 참조할 수 있어 코드가 간단해진다 ② 외부에 불필요하게 공개되지 않아 구현 디테일을 숨길 수 있다.

## 💻 코드 분석

**11.** 다음 코드를 설명하시오.
```java
class ButtonListener implements ActionListener {
  public void actionPerformed(ActionEvent e) {
    if (e.getSource() == jbtNew) System.out.println("Process New");
    else if (e.getSource() == jbtOpen) System.out.println("Process Open");
  }
}
```
> [!success]- 정답
> 하나의 listener를 여러 버튼에 등록하고, getSource()로 어떤 버튼이 눌렸는지 구분해 각기 다른 처리를 하는 "통합 listener" 방식이다.
