# 16장. Event-Driven Programming — 전체정리

> 15장에서 화면을 "그렸다"면, 이 장은 그 화면이 **사용자 동작에 반응하게** 만든다. 전체를 관통하는 한 문장은 **`program = { (event, handler) }`**. 버튼 클릭 같은 사건마다 처리기를 짝지어 등록하는 것이 전부다. 그 짝짓기를 하는 **3단계 절차**와 **listener interface**가 핵심.

## 1. 왜 이벤트 기반인가

- 미래 SW는 실생활 장비를 제어한다(자동차·자율주행·항공기·자판기 …).
- 외부 상황을 인지해 반응하는 **reactive system**.
- 이런 건 절차적으로 "1번 하고 2번 하고…"로 못 짠다. 언제 무슨 사건이 올지 모르니까.
- → **사건이 발생하면 그때 대응 처리**하도록 구성한다. 즉 **program = { (event, handler) }**.

## 2. Procedural vs Event-Driven

| | 실행 방식 |
| --- | --- |
| **Procedural** | 코드가 **절차 순서대로** 실행 |
| **Event-Driven** | **event가 활성화(activation)될 때** 해당 코드 실행 |

- 그래도 프로그램의 구성 요소는 여전히 `{ class }`(Java)다. 거기에 **(event, procedure) map/table**이 추가되는 구조.

## 3. Event (이벤트)란

- 어떤 사건이 일어났을 때, 그것을 프로그램에게 보내는 **신호(signal)**.
- 발생원:
  - **external user action**: mouse 이동/클릭, keystroke
  - sensor input 등 기타 **I/O**
  - **timer** 같은 operating system 생성 이벤트
- 같은 user 동작도 **GUI 요소에 따라 다른 event 의미**가 된다. 예: JButton에서의 클릭과 JComboBox에서의 클릭은 의미가 다르다.
- JVM이 keyboard/mouse의 저수준 동작을 **상위 수준 event로 변환·생성**해 준다.

## 4. Java Event-Driven 3단계 (★★ 이 장의 심장)

> "어떤 이벤트가 발생하면, 어떤 처리를 해라" — 이걸 3단계로 구현한다.

### ① "어떤 이벤트" 명시 = Event Source + Event Class
- "어디서(source)" + "어떤 종류(class)"를 특정한다.
- 예: `jbtOK`(source) + `ActionEvent`(class, 마우스 클릭으로 발생).

### ② "어떤 처리" 명시 = handler를 구현해 class화
- 처리할 동작을 메소드로 작성한다. Java에서 메소드는 홀로 못 있으니 **객체(class) 안에** 둔다.
- 이 메소드는 **시스템(JVM)이 upcall**한다. event를 알리고 관련 정보를 주고받는 과정을 JVM이 주관한다.
- 따라서 아무 메소드나 안 되고, **약속된 규정(Interface)대로 `implements`**해야 한다. → 이벤트 종류마다 Interface 규정이 다르다.

### ③ Event와 handler 연결 = event source에 등록
- 처리 메소드를 가진 객체(listener)를 만들어 source에 **등록**한다 (table entry가 생기는 셈).
- `jbtOk.addActionListener(new OKListener());`

```java
class OKListener implements ActionListener {
  public void actionPerformed(ActionEvent e) {
    // event handling actions
    System.out.println("OK button clicked");
  }
}
```

## 5. Event 정보 — getSource()

- event object는 그 event의 특성 정보를 **모두 담고 있다.**
- 이벤트를 발생시킨 **source object(인스턴스)**는 `getSource()`로 알아낸다.
- 예: 버튼 Action 이벤트가 왔을 때 "어떤 버튼이 눌렸나"를 판별할 때 쓴다.

## 6. User Action → Event 표 (★)

어떤 GUI 요소에서 어떤 동작을 하면 어떤 event가 나는지.

| User Action | Source Object | Event Generated |
| --- | --- | --- |
| 버튼 클릭 | JButton | **ActionEvent** |
| 체크박스 클릭 | JCheckBox | ItemEvent, ActionEvent |
| 라디오버튼 클릭 | JRadioButton | ItemEvent, ActionEvent |
| 텍스트필드에서 Enter | JTextField | ActionEvent |
| 콤보박스 항목 선택 | JComboBox | ItemEvent, ActionEvent |
| 윈도우 열기/닫기 등 | Window | WindowEvent |
| 마우스 누름/뗌 등 | Component | MouseEvent |
| 키 누름/뗌 등 | Component | KeyEvent |

## 7. Event별 Handler 규칙 (Listener Interface) (★)

이벤트 종류마다 구현할 interface와 handler method가 정해져 있다.

| Event Class | Listener Interface | Handler Method(s) |
| --- | --- | --- |
| ActionEvent | **ActionListener** | `actionPerformed(ActionEvent)` |
| ItemEvent | ItemListener | `itemStateChanged(ItemEvent)` |
| WindowEvent | WindowListener | `windowClosing`, `windowOpened`, `windowClosed` … |
| ContainerEvent | ContainerListener | `componentAdded`, `componentRemoved` |
| MouseEvent | MouseListener | `mousePressed`, `mouseReleased`, `mouseClicked`, `mouseEntered`, `mouseExited` |
| KeyEvent | KeyListener | `keyPressed`, `keyReleased`, `keyTyped` |

### 등록 예
```java
JButton jbt = new JButton("OK");
ActionListener listener = new OKListener();
jbt.addActionListener(listener);     // source에 listener 등록
```

## 8. Inner Class Listeners

- listener class는 component의 listener 객체를 만들기 위해 정의된다. 즉 **이벤트 처리기 = listener class.**
- 만약 그 listener를 **다른 곳에서 공유하지 않고** 특정 이벤트 전용으로만 쓴다면, **frame class 안에 inner class로** 정의하는 게 적합하다.

### Inner Class란
- 다른 class의 **member로 존재하는** class.
- **장점 1 (간단함)**: inner class는 자신을 감싼 outer class의 method/data를 **직접 참조**할 수 있다. outer의 참조를 일부러 넘겨주지 않아도 된다.
- **장점 2 (캡슐화)**: 불필요한 공개를 막는다 (구현 디테일 hiding).
- compile되면 **`OuterClassName$InnerClassName.class`**로 만들어진다.
- public/protected/private, static 선언 가능. (단 **static inner class는 outer의 non-static member에 접근 불가.**)

## 9. Anonymous Inner Class (★ 실무에서 제일 많이 봄)

- **이름 없는** inner class. **선언과 인스턴스 생성을 한 번에** 결합한 것.
```java
jbtOK.addActionListener(new ActionListener() {
  public void actionPerformed(ActionEvent e) {
    jlbClicked.setText("OK Clicked");
  }
});
```
- 반드시 superclass를 상속하거나 interface를 구현하지만, **`extends`/`implements`를 쓰지 않는다.**
- superclass/interface의 **모든 abstract method를 구현해야** 한다.
- compile되면 **`OuterClassName$1.class`, `$2.class`** … (번호가 매겨짐).

## 10. Listener 정의의 여러 방법 (정리)

같은 일을 하는 listener를 짜는 방법이 여러 가지다.
1. **별도 listener class**: `class OKListener implements ActionListener { ... }`
2. **inner class**: frame 안에 정의
3. **anonymous inner class**: 위 9번
4. **통합 listener**: 하나의 listener를 여러 버튼에 등록하고, `e.getSource()`로 구분
   ```java
   class ButtonListener implements ActionListener {
     public void actionPerformed(ActionEvent e) {
       if (e.getSource() == jbtNew) System.out.println("Process New");
       else if (e.getSource() == jbtOpen) System.out.println("Process Open");
     }
   }
   ```
5. **frame class 자체가 implements**: `public class Demo extends JFrame implements ActionListener` → `jbtNew.addActionListener(this);`

## 11. Window / Mouse / Key Events

- **WindowEvent**: Java component가 아닌 **윈도우 수준** 이벤트 (opened, closing, closed, activated, deactivated, iconified, deiconified). **JFrame에만** 연결 가능. (편의 클래스 `WindowAdapter`.)
- **MouseEvent**: 두 listener로 나뉨.
  - `MouseListener`: pressed, released, clicked, entered, exited
  - `MouseMotionListener`: dragging, moving
  - (편의 클래스 `MouseAdapter`.) 예제: 마우스로 메시지를 끌어 움직이기(MoveMessageDemo).
- **KeyEvent**: `keyPressed`(누름), `keyReleased`(뗌), `keyTyped`(눌렀다 뗌). `getKeyChar()`, `getKeyCode()`(VK_HOME, VK_END … 특수키).

## 12. Timer

- GUI가 아닌 component도 event를 발생시킬 수 있다.
- **`javax.swing.Timer`**: 미리 정한 주기마다 **ActionEvent**를 발생시키는 source. 주로 **animation**에 쓴다.
```java
Timer timer = new Timer(1000, new TimeoutHandler());  // 1000ms마다
timer.start();

class TimeoutHandler implements ActionListener {
  public void actionPerformed(ActionEvent e) { /* 매 초 실행 */ }
}
```
- 응용: 디지털 시계(매 초 갱신), 깃발 올라가는 애니메이션 등.
- (참고) `java.util.Timer` + `TimerTask`(run() 구현)도 별도로 존재.

## 정리 — 이 장의 핵심 한 줄
> **program = { (event, handler) }**. ① 이벤트(Source+Class) 정하고 ② 처리기를 **listener interface대로 구현**하고 ③ source에 **등록(addXxxListener)**한다. 핸들러는 프로그래머가 아니라 **JVM이 upcall**하므로 약속된 interface를 지켜야 한다.
