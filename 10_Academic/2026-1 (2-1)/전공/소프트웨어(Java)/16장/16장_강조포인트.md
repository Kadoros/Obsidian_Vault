# 16장. 강조포인트 ⭐

## 🔴 program = { (event, handler) }
- 절차적이 아니라 **사건 발생 시 대응**
- procedural(순서 실행) vs event-driven(event 활성화 시 실행)

## 🔴 Event-Driven 3단계 (★★ 시험 핵심)
1. **어떤 이벤트** = Event Source + Event Class
2. **어떤 처리** = handler를 Interface대로 implements (JVM이 **upcall**)
3. **등록/연결** = `addActionListener(...)`

## 🔴 왜 Interface대로 implements?
- 핸들러 method를 **시스템(JVM)이 upcall**하므로, 임의 method가 아니라 약속된 규정(Interface)을 지켜야 함

## 🔴 Event–Listener–Handler 짝 (★)
- ActionEvent – ActionListener – **actionPerformed**
- ItemEvent – ItemListener – itemStateChanged
- MouseEvent – MouseListener – mousePressed…
- KeyEvent – KeyListener – keyPressed/Released/Typed

## 🔴 getSource()
- event 발생 객체 확인. 통합 listener에서 버튼 구분에 사용

## 🔴 Anonymous Inner Class
- **선언 + 생성 한번에**, extends/implements **안 씀**
- abstract method 전부 구현, `Outer$1.class`

## 🔴 Inner Class 장점
- outer의 method/data 참조 가능 (참조 안 넘겨도 됨)
- 불필요한 공개 방지(hiding)

## 🟥 Timer
- `javax.swing.Timer`: 주기마다 **ActionEvent** → animation
- GUI 아닌 것도 event source가 될 수 있음
