# 12장. 강조포인트 ⭐

## 🔴 this 두 용도 (단골)
1. hidden field 참조: `this.radius = radius;`
2. 다른 constructor 호출: `this(1.0);` — **반드시 constructor 첫 줄**

## 🔴 클래스 설계 지침 (서술형 핵심)
- **통일성**: 한 class = 한 entity (Student/Staff 분리, 공통은 상속)
- **책임 분리**: String/StringBuilder/StringBuffer
- **재사용**: 지나친 최적화·특정 가정 금지
- 표준: **no-arg constructor + equals + toString**
- 배치 순서: **data → constructor → method**

## 🔴 Immutable 함정 (★★ 가장 잘 나옴)
- "private field만 있고 setter 없으면 immutable이다" → **틀림!**
- accessor가 **변경 가능한 내부 객체의 참조**를 반환하면 외부에서 바꿀 수 있음
```java
BirthDate date = student.getBirthDate();
date.setYear(2010);   // 내부가 바뀜 → mutable
```
- immutable 3조건: ① 모든 field private ② setter 없음 ③ **mutable 객체 참조 리턴하는 accessor 없음**

## 🔴 protected 등장 이유
- 클래스는 상속되므로 **상속 관계의 접근**도 지정 필요 → protected

## 🔴 추상화/캡슐화
- abstraction = 사용과 구현 **분리**
- 사용자는 구현을 몰라도 됨 (캡슐화로 숨김)

## 🟥 Top-down/Bottom-up
- 구현은 **Bottom-up**, 설계·분석은 **Top-down**
