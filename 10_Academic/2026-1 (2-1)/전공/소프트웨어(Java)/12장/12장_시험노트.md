# 12장. 시험노트 📝 (개념 정밀 정리)

## 용어 정의

| 용어 | 정의 |
| --- | --- |
| **class abstraction** | 클래스의 사용과 구현을 분리하는 것 |
| **class contract** | 클래스 설명과 사용법을 알려주는 것. 사용자는 구현을 몰라도 됨 |
| **this** | 객체 자신을 지칭. hidden field 참조, 다른 constructor 호출에 사용 |
| **protected** | 상속 관계(subclass)에서의 접근을 허용하는 modifier |
| **immutable object** | 생성 후 내용을 변경할 수 없는 객체 |

## this 두 가지 용도
1. 자신의 data field 명시적 참조 (`this.radius = radius;`)
2. 같은 class의 다른 constructor 호출 (`this(1.0);`)

## 변수 scope
- instance/static: class 전체, 어디서든 선언
- local: 선언 위치~블록 끝, **사용 전 명시적 초기화 필수**

## 클래스 설계 지침 5가지 (★서술 단골)
1. **통일성(coherence)**: 하나의 class = 하나의 entity. Student/Staff 합치지 말 것 → 공통은 상속
2. **책임 분리**: 기능을 여러 class로. String/StringBuilder/StringBuffer 예
3. **재사용**: 특정 가정/지나친 최적화 금지
4. **표준 요소**: no-arg constructor, equals override, toString
5. **스타일**: data → constructor → method 순서, 항상 초기화

## Immutable — 함정 주의 (★★)
- private field + setter 없음 ≠ 무조건 immutable
- accessor가 **변경 가능한 내부 객체의 참조**를 돌려주면 외부에서 변경 가능 → mutable
- immutable 조건:
  1. 모든 field private
  2. setter(mutator) 없음
  3. **mutable 객체 참조를 리턴하는 accessor 없음**

## 접근 지정자
- public / private / **protected**(상속용) / default
- private로 숨기고 필요한 것만 get/set

## Top-down vs Bottom-up
- 구현: **Bottom-up** (class/method 하나씩)
- 분석·최상위 설계: **Top-down**
