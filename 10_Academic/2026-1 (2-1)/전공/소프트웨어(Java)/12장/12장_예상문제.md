# 12장. 예상문제 ✏️

> 답은 `> [!success]- 정답` 토글 안에 숨김.

## ⭕❌ OX 문제

**1.** 모든 data field가 private이고 setter가 없으면 그 클래스는 무조건 immutable이다. (   )
> [!success]- 정답
> ❌ — accessor가 변경 가능한 내부 객체의 참조를 반환하면 외부에서 그 객체를 바꿀 수 있어 mutable이 된다.

**2.** this는 같은 class의 다른 constructor를 호출하는 데 쓸 수 있다. (   )
> [!success]- 정답
> ⭕ — `this(...)` 형태. 단 constructor의 첫 문장이어야 한다.

**3.** local 변수는 선언만 하면 자동으로 0으로 초기화된다. (   )
> [!success]- 정답
> ❌ — local 변수는 사용 전 반드시 명시적으로 초기화해야 한다(instance/static과 다름).

**4.** protected는 상속 관계의 접근을 허용하기 위해 도입되었다. (   )
> [!success]- 정답
> ⭕

## 🔤 빈칸 채우기

**5.** 클래스의 사용과 구현을 분리하는 것을 ________ 라고 한다.

## 📝 단답·서술형

**7.** 클래스 설계 지침 중 "통일성(coherence)"을 예와 함께 설명하시오.
> [!success]- 정답
> 하나의 class는 하나의 entity만 기술해야 한다. 예를 들어 Student는 학생만, Staff는 직원만 다루고 둘을 한 class로 합치지 않는다. 공통점이 많다면 상속으로 해결한다.

**8.** 다음 코드에서 Student가 immutable이 아닌 이유를 설명하시오.
```java
public BirthDate getBirthDate() { return birthDate; }
```
> [!success]- 정답
> getBirthDate()가 내부 BirthDate 객체의 참조를 그대로 반환한다. 외부에서 `student.getBirthDate().setYear(2010)`처럼 그 객체를 변경하면 Student 내부 상태가 바뀌므로 mutable이다.

**9.** Java 객체지향에서 구현은 bottom-up이 적합한 이유는?
> [!success]- 정답
> class 하나, method 하나씩 만들다 보면 전체가 완성되는 구조이기 때문. 단, 문제 분석과 최상위 설계는 top-down으로 한다.

## 💻 코드 분석

**10.** `this`의 역할을 설명하시오.
```java
public Circle(double radius) { this.radius = radius; }
```
> [!success]- 정답
> 파라미터 radius와 필드 radius의 이름이 같아 가려진(hidden) 상황에서, `this.radius`는 객체 자신의 필드를 명시적으로 가리킨다. 따라서 필드 ← 파라미터 대입이 된다.
