# 15장. GUI (1) — 전체정리

> 드디어 화면이 나오는 장. 큰 그림은 **"Frame 위에 component를 Layout 규칙으로 배치하고 보여준다"**이다. 교수님은 이 과정을 **PPT 슬라이드 만들기**에 비유한다. 이 비유 하나로 전체 흐름이 정리되니 꼭 잡고 가자.

## 1. Java GUI 만드는 과정 (PPT 슬라이드 만들기에 비유)

| PPT에서 그림 슬라이드 만들기 | Java GUI에서 대응 |
| --- | --- |
| 그림 그릴 **새 슬라이드 시작** | 화면 준비 — **Panel, Frame** class 정의 시작 |
| 메뉴판에서 **그림 요소 선택·배치** | GUI 요소 생성·배치: `new Label()`, Button, TextField … + **LayoutManager** 지정 후 add |
| 필요시 요소들 **grouping** | **Panel**로 묶기 (Panel을 또 다른 Panel/Frame에 add) |
| **슬라이드 프리젠테이션** (보여주기) | `new Frame()` → 지정한 화면의 실체가 보여짐 (`setVisible(true)`) |
| 하이퍼링크 등으로 **동작 추가** | 각 요소에 **event handler** 작성·연결 → (GUI요소, user action, handler) 테이블 (16장) |

이 5단계가 GUI 프로그램의 뼈대다. "준비 → 배치 → 묶기 → 보여주기 → 동작"으로 외우면 된다.

## 2. GUI Object 생성 예

각 component는 그냥 `new`로 만든다. 텍스트나 항목을 생성자 인자로 준다.
```java
JButton jbtOK = new JButton("OK");
JLabel jlblName = new JLabel("Enter your name: ");
JTextField jtfName = new JTextField("Type Name Here");
JCheckBox jchkBold = new JCheckBox("Bold");
JRadioButton jrbRed = new JRadioButton("Red");
JComboBox jcboColor = new JComboBox(new String[]{"Red","Green","Blue"});
```

## 3. Swing vs AWT (★)

질문: 왜 GUI 클래스 앞에 다 **J**가 붙나? (JButton — 그냥 Button은 왜 안 되나?)
- 답: `Button`은 이미 **java.awt** 패키지에 있어서 이름 충돌을 피하려고 J를 붙인다.

배경:
- Java 초창기 GUI = **AWT (Abstract Windows Toolkit)**.
- Java 2부터 더 강력·다양·유연한 **Swing**으로 대체됨.
- **Swing**: 대부분 Java 코드로 **바로 화면(canvas)에 그린다.** 그래서 플랫폼 의존이 적고 기본 GUI 자원을 덜 쓴다 → **lightweight component**.
- **AWT**: 플랫폼의 기본 GUI에 의존해서 그린다 → **heavyweight component**.

### Container Class & Helper Class
- **Container class**: 다른 GUI component를 **담을 수 있는** class (JFrame, JPanel 등).
- **Helper class**: component의 **하위 클래스가 아니라**, color·font·dimension처럼 component의 **속성을 설명**하는 class (Color, Font, Dimension, Graphics 등). → component와 helper를 구분하는 게 포인트.

## 4. Frame

- **Frame** = 다른 창 안에 포함되지 않은 **최상위 창**. Java GUI 앱에서 다른 UI component를 담는 기본 컨테이너.
- Swing에서는 **JFrame** class로 새 window를 만든다.

```java
JFrame frame = new JFrame("Test Frame");
frame.setSize(400, 300);                 // 크기
frame.add(new JButton("OK"));            // component 추가
frame.setVisible(true);                  // 화면에 보이기
frame.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);  // X 누르면 종료
```

### content pane
- 원래는 component를 frame의 **content pane**에 넣어야 했다: `frame.getContentPane().add(...)`.
- **JDK 1.5부터** `frame.add(...)`라고 쓰면 자동으로 content pane에 위임된다. (편의 기능.)

### Java 스타일 — JFrame 상속
실무에서는 JFrame을 직접 상속해 나만의 프레임 class를 만든다.
```java
public class MyFrame extends JFrame {
  public MyFrame() {
    super("Test Frame");                 // = setTitle("Test Frame")
    setSize(400, 300);
    add(new JButton("OK"));
    setVisible(true);
    setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
  }
}
// 사용: new MyFrame();
```

## 5. Layout Managers (★ 시험 단골)

모든 component를 일일이 좌표로 손배치할 수는 없다. **Layout manager**가 일정한 규칙에 따라 component를 **자동 배치**한다.
- UI component는 container 안에 배치된다. 그래서 각 container는 내부 배치를 담당하는 Layout manager를 가진다.
- `container.setLayout(LayoutManager)`로 설정.

| Layout | 배치 방식 |
| --- | --- |
| **FlowLayout** | 넣은 **순서대로** 줄을 따라 흐르게 (왼→오, 넘치면 다음 줄) |
| **GridLayout** | **격자(행 × 열)**로 칸칸이 |
| **BorderLayout** | **5영역**: North, South, East, West, Center |

```java
frame.setLayout(new FlowLayout());
frame.add(new JButton("Ok"));
frame.add(new JButton("Cancel"));

// BorderLayout은 위치 constraint를 함께 지정
add(component, BorderLayout.EAST);
// constraint: NORTH / SOUTH / EAST / WEST / CENTER
```

## 6. Panel (sub-container)

- **Panel** = UI component를 **그룹화**하는 sub-container.
- 권장 방식: 먼저 panel에 component들을 배치하고, 그 panel을 frame에 배치한다 (main frame 위에 sub-panel을 얹는 구조).
- JFrame에 add하면 실제로는 content pane에 추가되는 것이고, Panel에 add하면 panel에 직접 추가된다.

### JPanel 생성
- `new JPanel()` → 기본 layout이 **FlowLayout**인 패널.
- `new JPanel(LayoutManager)` → 특정 layout 지정.
```java
JPanel p = new JPanel();
p.add(new JButton("OK"));
```

### 예제 — 전자레인지 (TestPanels)
ButtonPanel(GridLayout 4×3에 숫자/Start/Stop 버튼)을 만들고, BorderLayout을 쓰는 frame에 텍스트필드(NORTH)+버튼판(CENTER)을 조합해 전자레인지 UI를 만든다. → **panel을 레고처럼 조립**하는 전형.

## 7. 화면 (데이터) 갱신

표시할 값이 바뀌었을 때:
- `setText("new value")` — 텍스트 변경
- `remove()` / `add(new component)` — component 교체
- `repaint()` / `revalidate()` — 다시 그리기/레이아웃 재계산

## 8. Color & Font

### Color (java.awt.Color) — RGB model
```java
Color c = new Color(r, g, b);          // 각 0(검정)~255(흰색)
Color c = new Color(228, 100, 255);
jbt.setBackground(Color.yellow);       // 배경색
jbt.setForeground(Color.red);          // 전경색(글자색)
```
- 13가지 표준색이 정의됨. 소문자(`Color.red`)는 Java 명명 규칙에 안 맞아서, **JDK 1.4부터 대문자 상수**(`Color.RED`, `Color.DARK_GRAY` …)가 추가됐다.

### Font (java.awt.Font)
```java
Font myFont = new Font("SansSerif", Font.BOLD, 16);
Font myFont = new Font("Serif", Font.BOLD + Font.ITALIC, 12);  // 스타일 합치기
jbtOK.setFont(myFont);
```
- 모든 플랫폼 지원 표준 글꼴: **SansSerif, Serif, Monospaced, Dialog, DialogInput**.
- Style: `Font.PLAIN(0)`, `Font.BOLD(1)`, `Font.ITALIC(2)`, `Font.BOLD + Font.ITALIC(3)`.

## 9. Borders & Icons

### Border
```java
panel.setBorder(new TitledBorder("My Panel"));       // 제목 테두리
panel.setBorder(new LineBorder(Color.black, 2));      // 선 테두리(색, 굵기)
```

### ImageIcon
```java
ImageIcon icon = new ImageIcon("image/us.gif");
new JLabel(icon);          // 라벨에 그림
jbtOk.setIcon(icon);       // 버튼에 그림 (setText 대신)
```
- Icon = 고정 크기의 작은 그림, component를 꾸미는 용도.

## 10. (참고) 복합 component

- **JScrollPane**: 스크롤 영역 제공. `new JScrollPane(jpPictures)`로 감싼 뒤 add.
- **JTable**: **Table Model**(DefaultTableModel)을 통해 **간접적으로** 다룬다.
  ```java
  DefaultTableModel model = new DefaultTableModel();
  model.setColumnIdentifiers(headers);
  JTable table = new JTable(model);
  value = model.getValueAt(row, col);
  model.setValueAt(value, row, col);
  model.addRow(fields);
  model.fireTableDataChanged();   // 변경 통지
  ```

## 정리 — 이 장의 핵심 한 줄
> **JFrame(최상위 창)** 위에 **Panel/component**를 얹고, **Layout Manager(Flow/Grid/Border)**로 배치한 뒤 `setVisible(true)`로 보인다. Swing은 J로 시작하는 lightweight, AWT는 heavyweight.
