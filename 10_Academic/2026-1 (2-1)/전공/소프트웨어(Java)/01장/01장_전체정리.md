# 1장. Java Introduction — 전체정리

## 1. Java vs C 프로그램 차이

같은 "1부터 10까지 합" 프로그램을 비교하면 **문법은 유사**하지만 구조가 다르다. Java는 **C에서 출발**했다.

| 구분 | C | Java |
| --- | --- | --- |
| 1등 시민(주체) | **함수(function)** | **클래스(class)** |
| 구성 | 프로그램 = 함수들의 모음 | 프로그램 = class들의 모음 |
| 함수의 위치 | 독립적으로 존재 | class에 부속되는 2등급 → **method**라 부름 |
| 호출 | `main()` | `FirstJava.main()` (class 통해서만) |

**기타 차이점**
- pre-processor 없음
- header file(`*.h`) 없음
- `String` 타입 별도 제공; `char*` 없음 → **pointer 개념 없음**
- `public`, … 같은 접근 제어자 존재

## 2. class란 무엇인가?

> 언어 종류·문법을 떠나서, 프로그램은 무엇으로 구성되는가?

- **C: { functions [+ data types] }** — 함수 중심
- **Java: { classes }** — 클래스 중심
- 따라서 **class = functions + data type**, 더 정확히는 **class = [data] + [func]**

**class의 두 얼굴**
- `class = 함수` 예: 자료구조 없이 method만 (함수를 싸놓은 틀)
- `class = 자료구조` 예: `class Point { float x; float y; }` → C의 **struct 기능**
- 실제로는 둘을 합침: `class Point`는 `(x, y)` 데이터 + `distance()`, `move()`, `print()` 등 관련 함수

```java
public class Point {
  private double x;
  private double y;
  Point() { x = 0.0; y = 0.0; }
  Point(double vx, double vy) { x = vx; y = vy; }
  double getX() { return x; }
  double getY() { return y; }
  double distance(Point p) {
    double dx = x - p.getX();
    double dy = y - p.getY();
    return Math.sqrt(dx*dx + dy*dy);
  }
  void move(double dx, double dy) { x += dx; y += dy; }
  void print() { System.out.println("X = " + x + " Y = " + y); }
}
```

## 3. 프로그래밍 방식 차이 (시험 핵심)

| Java : { classes } | C : { functions [+ data types] } |
| --- | --- |
| class = `<[data] + [func]>` | 자료구조·함수 각각 별도 |
| 자료구조와 함수를 구조화 → **캡슐화(encapsulation)** | 프로그래머가 file로 구조화 → **캡슐화 안 됨**(함수 이름 충돌) |
| 자료구조 중심, 함수를 부속화 `Address.sort()` | 함수 중심 `sort(address)` |
| **object-oriented / entity description / event-driven** | **action-oriented / procedural description / control** |

## 4. 프로그램 실행 방법

**전통 방식 2가지**
- **컴파일 방식 (C)**: `cc -o test test.c` → 실행파일 `test`
- **인터프리터 방식 (Python 등 script)**: `python test.py` → 인터프리터가 직접 실행

**Java 방식 = compile + interpret (혼합)**

```
test.java → [Java Compiler] → test.class → [Java Interpreter(JVM) 안에서 실행]
```

- **JVM (Java Virtual Machine)**: Java interpreter가 프로그램을 수행하는 환경/방식. interpreter 안의 가상 머신.
- **Byte code**: Java 컴파일러가 만드는 중간 코드. JVM의 기계어. interpreter가 해석.

**실행 명령 비교**

| Python | C | Java |
| --- | --- | --- |
| `python first-sum.py` | `gcc first-sum.cc` → `a.out` | `javac FirstJava.java` → `FirstJava.class` |
| (바로 실행) | `./a.out` | `java FirstJava` |

- 컴파일하는 것은 동일 (`javac` vs `gcc`)하나 **결과물이 다름** (`FirstJava.class` vs `a.out`)
- 중간코드는 바이너리보다 상위 수준 → **다른 시스템에서도 java 인터프리터로 실행 가능** (이식성)

## 5. 실행 방법 Why? + 비교/요약

- **Interpreter 방식 장점**: 즉시 수행, portability, security
- **Compiler 방식 장점**: execution speed, preprocessing 통한 SW공학적 장점(1차 오류 점검, strongly typed)

| 항목 | 우열 |
| --- | --- |
| 실행 시 성능 | **C > Java > Python** |
| 실행 편의성 | Python > C ? Java |
| 프로그램 호환성 | **Python > Java > C** |
| 보안성 | Python = Java > C |
| 대형 프로그램 가능? | **Java = C > Python** |

## 6. Java History & 특징

- **Java, May 20, 1995, Sun World** 발표
- 목적: object-oriented / Internet / small & portable / general purpose programming language
- 모든 Web browser가 Java Interpreter 내장 → Applets, Web Applications, Smart phone app 개발

**Characteristics of Java** (11가지)
Simple / **Object-Oriented** / Distributed / **Interpreted** / **Robust** / **Secure** / **Architecture-Neutral** / **Portable** / Performance / Multithreaded / Dynamic

**JDK Editions**
- **J2SE** (Standard) — 이 강의/교재 기준
- J2EE (Enterprise) — servlets, ServerPages 등 서버 응용

**IDE**: NetBeans(Sun), Visual Studio, **Eclipse**(IBM)

## 7. Anatomy of a Java Program

구성 요소: Comments(주석) / Reserved words(예약어) / Modifiers(제어자) / Statements(구문) / Blocks(블록) / Classes(클래스) / Methods(메소드) / main method

**Comments — 3종류**
- **Line comment**: `//` 줄 앞에 slash 두 개
- **Paragraph comment**: `/* ... */` 한 줄~여러 줄
- **javadoc comment**: `/** ... */` — classes, data, methods 문서화. JDK의 Javadoc 명령으로 HTML 생성.

**Modifiers**: data/methods/classes의 속성과 사용법 명시. 예: `public`, `static`, `private`, `final`, `abstract`, `protected` (6장에서 재론)

**Blocks**: 한 쌍의 brace `{ }`가 컴포넌트를 묶어 블록 형성 (class block, method block)

**Methods**: 기본적으로 함수(function/procedure). 반드시 클래스 안에 포함. `ClassName.methodName();` 예) `System.out.println();`

**main method**: Program entry point. Java interpreter가 main method 호출로 프로그램 실행.
```java
public static void main(String[] args) {
  // Statements;
}
```

## 8. 첫 GUI & Method Overloading

**Message Dialog**: `showMessageDialog`는 `JOptionPane` 클래스에 포함 (Java system 사전 정의 클래스)
```java
JOptionPane.showMessageDialog(null, "Welcome to Java!");
JOptionPane.showMessageDialog(null, "Welcome to Java!",
    "Display Message", JOptionPane.INFORMATION_MESSAGE);
```

**Method Overloading**: 같은 이름의 메소드를 여러 형태로 정의하고, 호출 시 **인자 수·형**으로 적합한 형태 자동 결정.
- 같은 의미 메소드에 어색한 이름(`sumI()`, `sumF()` …) 따로 지을 필요 없음
- 인자 수/형 미리 고민 불필요, 안 쓰는 형태도 정리 불필요
- **정리: 프로그램 관리 편의성 제공** — "정리하려고 하지 말라!", "결국 필요하게 된다." (캡슐화와 함께)
