# 10장. Class 기본 (3) — 전체정리

> 이 장의 핵심 축은 딱 하나, **static이냐 instance냐**다. "이 변수/메소드는 객체마다 따로인가, 아니면 클래스 전체가 공유하는가?"를 구분하는 감각이 전부라고 봐도 된다. 뒤에 class·local 변수의 가시성(visibility)이 보너스로 붙는다.

## 1. Instance vs Static

### Instance variable / method
- **객체(object)는 클래스의 instance**라고 부른다.
  - 비유: **붕어빵은 붕어빵 틀에서 나온 instance.** 틀(class) 하나로 붕어빵(object) 여러 개를 찍어낸다.
- **instance 변수** = 특정 instance(object)에 속한 변수. 객체 변수라고도 한다. 객체마다 **각자의 값**을 가진다.
- **instance 메소드** = 객체를 통해 실행된다 (`obj.method()`).
- 규칙: **`static`이 안 붙어 있으면 전부 instance.**

### Static variable / constant / method
- `static`은 특정 object에 묶이지 않는다 → **클래스 소속**. 그래서 class variable / class method라고도 부른다.
- **static 변수는 class의 모든 instance가 공유한다.** 한 객체가 바꾸면 모든 객체에서 바뀐 값이 보인다.
- 접근은 **클래스를 통해서**가 원칙: `Circle2.getNumberOfObjects()`. (객체를 통해서도 되긴 하지만 권장하지 않음.)
- **static constant** = `final` + `static`. 모든 instance가 공유하는 상수. 예: `static final double PI = 3.14159;`
- static을 만들려면 반드시 `static` 키워드를 붙여야 한다.

```java
public class Circle2 {
  double radius;                    // instance 변수 (객체마다 따로)
  static int numberOfObjects = 0;   // static 변수 (전체 공유)

  Circle2() { radius = 1.0; numberOfObjects++; }
  Circle2(double newRadius) { radius = newRadius; numberOfObjects++; }

  static int getNumberOfObjects() { return numberOfObjects; }  // static
  double getArea() { return radius * radius * Math.PI; }        // instance
}
```

대표 헷갈림:
- `Circle2.radius` → **❌** radius는 instance 변수라 객체 없이 클래스로 접근 불가.
- `Circle2.getNumberOfObjects()` → ⭕ static이니 클래스로 접근이 정상.
- `c1.getNumberOfObjects()` → 되긴 하지만 비권장(static을 객체로 부르는 건 혼란).

## 2. static / instance 공간 개념

머릿속 그림이 중요하다.
- **static 변수**는 클래스당 **딱 하나의 공간**. 모든 객체가 그 한 칸을 같이 본다.
- **instance 변수**는 **객체를 new 할 때마다 따로** 공간이 생긴다.

그래서 `numberOfObjects`는 객체를 아무리 많이 만들어도 카운터가 하나라 "총 몇 개 만들었나"를 셀 수 있고, `radius`는 객체마다 달라서 원1의 반지름과 원2의 반지름이 독립적이다.

## 3. static 메소드에서의 접근 규칙 (★★ 가장 자주 나옴)

같은 class 안의 **static 메소드(대표적으로 `main()`)**에서 다른 멤버에 접근할 때:

- **static member** → reference 변수(객체) 없이 **바로** 접근 가능.
- **non-static(instance) member** → 반드시 **reference 변수(객체)를 통해서**.

```java
public static void main(String[] args) {
  int n = numberOfObjects;     // static → 바로 OK
  Circle2 c1 = new Circle2();
  c1.radius = 9;               // instance → 반드시 객체(c1) 통해서
}
```

**왜?** static 메소드는 특정 객체 없이도 돌아가는데(클래스 소속), instance member는 "어느 객체의 것이냐"가 정해져야 의미가 있기 때문이다. 객체를 안 정하고 instance를 부르면 "누구의 radius?"라는 답이 없다.

### 잘못된 static 사용 (단골 함정)
`main()`이 static이라는 이유만으로 **모든 메소드를 static으로 만드는 것**이 최악의 패턴이다.
```java
public static void main(String[] args) {
  Circle2 c1 = new Circle2();
  int n = getNumberOfObjects();   // static끼리라 OK
  double d = getArea();           // ❌ getArea는 instance인데 객체 없이 호출
}
```
- `getArea()`는 instance 메소드라 "어느 원의 넓이?"가 필요한데 객체 없이 불러 **컴파일 에러**.
- **해결:** 객체를 만들어 `c1.getArea()`로 부르거나, 정말 객체와 무관한 거라면 static을 빼라.

## 4. 무엇을 static으로 선언할 것인가? (설계 판단)

- **개별 instance(object)의 속성** → **non-static.** 반드시 instance가 지정돼야 의미가 있는 것 (예: 반지름, 이름).
- **개별 instance와 무관한 것** → **static.** instance를 지정하면 오히려 이상하고, class를 통해 접근하는 게 정상 (예: 생성된 객체 수, 원주율 같은 공통 상수).

그리고 교수님이 짚는 미묘한 포인트:
- **공유 여부는 고려 사항 중 하나일 뿐**이다. "공유하면 공간이 절약되니까 static" 같은 사고는 위험.
- **공유해야만 하는 경우에만** static을 쓴다.
- 공유 안 해도 되는데 단지 공간 이익 때문에 static으로 묶으면, 객체 독립성이 깨져서 오히려 안 좋다.

## 5. Visibility of Classes (클래스 자체의 가시성)

지금까지는 변수·메소드의 가시성이었고, 이제 **class 자체**의 가시성.

### 한 파일에 여러 class를 둘 수 있나?
- **가능하다.** 단 제약이 있다:
  - **public class는 파일당 하나** (파일 이름 = public class 이름).
  - **top-level class에는 private를 못 붙인다.**

```java
public class Bookmark {          // public — 파일명 Bookmark.java
  public Bookmark() {}
}
class BookmarkGroup {            // public 아님 — 같은 파일에 둬도 OK
  BookmarkGroup() {}
}
```

### Inner class (nested class)
- **class 안에 정의된 class.**
- `static` nested class도 가능.
- **inner class에는 private를 붙일 수 있다** (top-level과 다른 점!).

```java
public class Bookmark {
  public Bookmark() {}
  private class BookmarkGroup {   // private inner class — OK
    BookmarkGroup() {}
  }
}
```

### Visibility of Local Variables
- local 변수에 `static` → **❌**
- `public` / `private` → **❌**
- **`final`만 가능** → final local 변수는 그 메소드 안에서 **상수** 취급.

## 정리 표

| 대상 | static | public/private | final |
| --- | --- | --- | --- |
| top-level class | (static 의미 다름) | public O, **private X** | O |
| inner class | O | public/private/protected **모두 O** | O |
| local variable | **X** | **X** | **O (유일하게 허용)** |

## 정리 — 이 장의 핵심 한 줄
> **static = 클래스 소속(전부 공유), instance = 객체 소속(각자).** static 메소드에서 instance 멤버는 **반드시 객체를 통해** 써야 하고, `main`이 static이라고 다 static으로 만들면 안 된다.
