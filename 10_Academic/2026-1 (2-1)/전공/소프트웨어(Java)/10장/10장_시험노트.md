# 10장. 시험노트 📝 (개념 정밀 정리)

## 용어 정의

| 용어 | 정의 |
| --- | --- |
| **instance** | 클래스로부터 만들어진 객체 (붕어빵 = 틀에서 나온 instance) |
| **instance 변수/메소드** | 특정 객체에 속함, 객체를 통해 접근/실행. static 안 붙으면 전부 instance |
| **static 변수(class 변수)** | 특정 객체가 아닌 클래스 소속, 모든 instance가 **공유** |
| **static method** | 클래스 소속 메소드, 클래스를 통해 접근하는 것이 원칙 |
| **static constant** | `static final`, 공유되는 상수 |
| **inner class** | 다른 class 안에 정의된 class (nested) |

## static에서의 접근 규칙 (가장 중요)

static 메소드(예 `main()`)에서:
- static → **reference 없이** 바로 접근
- non-static → 반드시 **reference 변수(객체)를 통해서**

이유: static은 객체가 없어도 존재하지만, instance member는 객체가 있어야 의미가 있기 때문.

## 잘못된 static (함정)

- `main()`이 static이라고 **모든 메소드를 static**으로 만드는 것 = 최악
- static 안에서 `getArea()`(instance) 직접 호출 → **컴파일 에러**
- 해결: 객체 생성 후 `c1.getArea()` 또는 진짜 instance 속성이면 static 제거

## 무엇을 static으로?

| 속성 종류 | 선언 |
| --- | --- |
| 개별 객체 속성 (객체 지정해야 의미) | non-static |
| 개별 객체와 무관, 클래스로 접근이 정상 (예: 객체 수) | static |

- 공유는 **고려 사항일 뿐**. 공유 꼭 필요할 때만 static
- 공간 이익만으로 공유? → 안 하는 게 좋음 (독립성)

## 접근 예 (Circle2)

- `Circle2.radius` ❌ (radius는 instance)
- `Circle2.getNumberOfObjects()` ⭕ (static, 클래스로)
- `c1.getNumberOfObjects()` △ (되지만 비권장)

## Visibility of Classes

- **한 파일에 여러 class 가능**, 단 **public class는 1개**
- top-level class에 **private 불가**
- **inner class**: static 가능, **private 가능**, public/protected도 가능

## Local variable modifier

- static ❌, public/private ❌
- **final만 가능** → 메소드 내 상수
