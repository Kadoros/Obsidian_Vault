## 1. 실주소 모드 (Real-Address Mode)

16비트 모드 프로그램의 특징:
- **최대 1MB**의 RAM만 주소 지정 가능
- **단일 태스킹(single tasking)**
- **메모리 경계 보호 없음** (앱이 어느 영역이든 접근 가능)
- **오프셋이 16비트**

> IBM PC-DOS가 IBM-PC 최초의 실주소 OS. Gary Kildall의 **CP/M**(Digital Research)에 뿌리. 이후 Microsoft 소유의 **MS-DOS**로 개명.

---

## 2. 세그먼트 메모리 (Segmented Memory)

절대(선형) 주소 = **16비트 세그먼트 값 × 16 + 16비트 오프셋**.

### 선형 주소 계산법
1. 세그먼트 값에 **16을 곱함**(= 16진수 0을 하나 붙임).
2. 오프셋을 더함.

**예: `08F1:0100` → 선형 주소**
```
조정된 세그먼트:  08F1 0   (×16)
오프셋 더하기:    + 0100
─────────────────────────
선형 주소:         09010
```
> 🔑 세그먼트를 한 자리 왼쪽 시프트(×16)한 뒤 오프셋을 더한다. → [[14장_강조포인트]]

## 3. MS-DOS 메모리 맵 (낮은 주소 → 높은 주소)

| 주소 | 영역 |
|------|------|
| 00000 | **Interrupt Vector Table (IVT)** |
| 00400 | BIOS & DOS Data |
| | Software BIOS |
| | DOS Kernel, Device Drivers |
| | Resident Command Processor |
| ~ | **Transient Program Area** (앱이 사용, 640K RAM 내) / Transient Command Processor |
| A0000 | Video Graphics |
| B8000 | Video Text & Graphics (VRAM) |
| C0000 | Reserved (device controllers) |
| F0000~FFFFF | **ROM BIOS** |

## 4. 소프트웨어 인터럽트 & INT 명령어

### INT 명령어
- **소프트웨어 인터럽트**를 실행. 처리 코드 = **인터럽트 핸들러(interrupt handler)** = **ISR(Interrupt Service Routine)**.
```
INT number        ; number = 0..FFh
```
- **IVT**는 각 인터럽트 핸들러의 **32비트 세그먼트-오프셋 주소**를 저장.

### 인터럽트 벡터링 과정 (4단계)
1. 호출 프로그램이 `int 10h` 실행 → IVT의 해당 엔트리 참조.
2. IVT 엔트리(예: `F000:F065`)에서 핸들러 주소를 얻어 점프.
3. 인터럽트 핸들러 실행(`sti / cld / push es / ... / IRET`).
4. `IRET`로 호출 프로그램의 다음 명령으로 복귀.

### 자주 쓰는 인터럽트 (Common Interrupts)
| INT | 서비스 |
|-----|--------|
| **10h** | Video Services (비디오) |
| **16h** | Keyboard Services |
| **17h** | Printer Services |
| **1Ah** | Time of Day |
| **1Ch** | User Timer Interrupt |
| **21h** | **MS-DOS Services** ← 가장 중요 |

## 5. MS-DOS 함수 호출 (INT 21h)

**공통 패턴**: 기능 번호를 **AH**에 넣고 `int 21h`. 부가 인자는 AL/DL/DX 등에.

### 5-1. INT 4Ch — 프로세스 종료
```asm
mov ah, 4Ch        ; 프로세스 종료
mov al, 0          ; 반환 코드 (0 = 정상)
int 21h
; .EXIT 0 과 동일
```

### 5-2. ASCII 제어 문자 (많은 INT 21h가 처리)
| 코드 | 의미 |
|------|------|
| 08h | Backspace (왼쪽 한 칸) |
| 09h | Horizontal Tab |
| 0Ah | Line Feed (다음 줄) |
| 0Ch | Form Feed (다음 인쇄 페이지) |
| 0Dh | Carriage Return (가장 왼쪽 열) |
| 1Bh | Escape |

### 5-3. 출력 함수 (Output)
| AH | 기능 |
|----|------|
| 02h, 06h | 문자 1개를 **표준 출력**에 |
| 05h | 문자 1개를 **기본 프린터**에 |
| 09h | **문자열**을 표준 출력에 (`$`로 끝나야 함) |
| 40h | 문자열을 **파일/장치**에 |

```asm
; 02h: 문자 'A' 출력
mov ah, 02h
mov dl, 'A'
int 21h

; 09h: 문자열 출력 ($ 종료, DS:DX = 주소)
.data
string BYTE "This is a string$"
.code
mov ah, 9
mov dx, OFFSET string
int 21h

; 40h: 문자열을 콘솔(핸들 1)에 쓰기
.data
message BYTE "Writing a string to the console"
bytesWritten WORD ?
.code
mov ah, 40h
mov bx, 1                  ; 핸들 (콘솔=1)
mov cx, LENGTHOF message   ; 쓸 바이트 수
mov dx, OFFSET message     ; DS:DX = 주소
int 21h
mov bytesWritten, ax       ; 실제 쓴 바이트 수
```

### 5-4. 입력 함수 (Input)
| AH | 기능 |
|----|------|
| 01h, 06h | 표준 입력에서 문자 1개 |
| 0Ah | 표준 입력에서 **버퍼 배열** 읽기 |
| 0Bh | 표준 입력 버퍼 **상태** 확인 |
| 3Fh | **파일/장치**에서 읽기 |

```asm
; 01h: 문자 1개 (에코O, 입력 대기O, Ctrl-Break 검사)
mov ah, 01h
int 21h
mov char, al

; 06h: 문자 1개 (에코X, 대기X) — ZF로 입력 유무 검사
L1: mov ah, 06h
    mov dl, 0FFh           ; 입력 대기 안 함
    int 21h
    jz  L1                 ; 문자 없으면 반복
    mov char, al
```
**0Ah — 버퍼 입력 (KEYBOARD 구조체 필요)**
```asm
count = 80
KEYBOARD STRUCT
    maxInput   BYTE count        ; 최대 입력 수
    inputCount BYTE ?            ; 실제 입력 수
    buffer     BYTE count DUP(?) ; 입력 문자 저장
KEYBOARD ENDS
.data
kybdData KEYBOARD <>
.code
mov ah, 0Ah
mov dx, OFFSET kybdData
int 21h
```
**3Fh — 파일/장치에서 읽기**
```asm
.data
inputBuffer BYTE 127 dup(0)
bytesRead   WORD ?
.code
mov ah, 3Fh
mov bx, 0                   ; 키보드 핸들
mov cx, 127                 ; 최대 바이트
mov dx, OFFSET inputBuffer
int 21h
mov bytesRead, ax
```

### 5-5. 응용 예: 문자열 암호화 (XOR)
표준 입력을 읽어 각 바이트를 XOR로 암호화 후 출력.
```asm
XORVAL = 239               ; 0~255 아무 값
.code
main PROC
    mov ax, @data
    mov ds, ax
L1: mov ah, 6              ; 직접 콘솔 입력
    mov dl, 0FFh
    int 21h
    jz  L2                 ; ZF=1 (EOF)이면 종료
    xor al, XORVAL         ; 암호화
    mov ah, 6              ; 출력
    mov dl, al
    int 21h
    jmp L1
L2: exit
```
> 💡 XOR 암호화는 **같은 키로 한 번 더 XOR하면 복호화** 된다(대칭).

### 5-6. 날짜/시간 함수
| AH | 기능 | 반환/입력 |
|----|------|-----------|
| 2Ah | Get system date | CX=년, DH=월, DL=일, AL=요일 |
| 2Bh | Set system date | CX=년, DH=월, DL=일 (실패 시 AL≠0) |
| 2Ch | Get system time | CH=시(0-23), CL=분, DH=초 |
| 2Dh | Set system time | CH=시, CL=분, DH=초 (실패 시 AL≠0) |

## 6. 표준 MS-DOS 파일 I/O 서비스

| AH/AX | 기능 |
|-------|------|
| **716Ch** | 파일 생성 또는 열기 |
| **3Eh** | 파일 핸들 닫기 |
| **42h** | 파일 포인터 이동 |
| **5706h** | 파일 생성 날짜/시간 얻기 |

### 716Ch — 파일 생성/열기 (확장)
입력 레지스터:
- `AX = 716Ch`
- `BX` = 접근 모드 (0=읽기, 1=쓰기, 2=읽기/쓰기)
- `CX` = 속성 (0=normal, 1=read-only, 2=hidden, 3=system, 8=volume ID, 20h=archive)
- `DX` = 동작 (1=open, 2=truncate, **10h=create**)
- `DS:SI` = 파일명 주소
- `DI` = alias hint (선택)
- 실패 시 **CF=1**, 성공 시 AX=핸들, CX=취한 동작

```asm
; 새 파일 생성 (읽기/쓰기, create+truncate)
mov ax, 716Ch
mov bx, 2                  ; read-write
mov cx, 0                  ; normal
mov dx, 10h + 02h          ; create + truncate
mov si, OFFSET Filename
int 21h
jc  failed                 ; CF=1이면 실패
mov handle, ax

; 기존 파일 열기 (읽기 전용)
mov ax, 716Ch
mov bx, 0                  ; read-only
mov cx, 0
mov dx, 1                  ; open existing
mov si, OFFSET Filename
int 21h
jc  failed
mov handle, ax
```

### Irvine16 라이브러리 — ReadString
표준 입력에서 문자열을 읽어 **null로 끝나는 문자열** 반환. DX=버퍼 포인터, CX=최대 문자 수+1. **CX−1 입력 또는 Enter** 시 반환. EAX=실제 읽은 문자 수.
```asm
.data
buffer BYTE 20 DUP(?)
.code
mov dx, OFFSET buffer
mov cx, LENGTHOF buffer
call ReadString
```
**구현 핵심**: `int 21h`(AH=1)로 문자 읽어 `[si]`에 저장, `0Dh`(Enter)면 종료, 마지막에 null 바이트 삽입, `AX = 원래개수 − CX`로 길이 반환.

## 7. 한 줄 요약
- **실주소 모드**: 1MB, 단일 태스킹, 세그먼트:오프셋(세그×16+오프셋).
- **INT 명령어**: IVT를 통해 핸들러(ISR) 호출, IRET로 복귀.
- **INT 21h**: AH=기능번호. 출력(02/09/40h), 입력(01/06/0Ah/3Fh), 날짜/시간(2A~2Dh).
- **파일 I/O**: 716Ch(생성/열기), 3Eh(닫기), 42h(포인터 이동). 실패는 CF=1.
