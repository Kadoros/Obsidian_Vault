## 1. 디스크 저장 시스템 (물리적 지오메트리)

**물리적 디스크 지오메트리(physical disk geometry)** = 시스템 BIOS가 디스크를 읽을 수 있도록 구조를 기술하는 방식.

| 용어 | 정의 |
|------|------|
| **Track(트랙)** | 데이터를 담은 **동심원(concentric circle)** |
| **Sector(섹터)** | 트랙의 한 조각(part of a track), 보통 **512바이트** |
| **Cylinder(실린더)** | **한 헤드 위치에서 읽을 수 있는 모든 트랙**(여러 플래터의 같은 반지름 트랙) |
| **Seek(탐색)** | 읽기/쓰기 헤드를 트랙 사이로 이동 |

### 단편화 (Fragmentation)
- **단편화된 파일** = 섹터들이 디스크의 **연속된 영역에 있지 않은** 파일.
- 결과: 헤드가 건너뛰어야 함 → **느린 접근**, 읽기/쓰기 오류 가능.

## 2. 파일 시스템 (File System)

파일 시스템이 해주는 일:
- **할당/여유 공간 추적**
- **디렉터리와 파일명 유지**
- 각 파일·디렉터리의 **섹터 위치 추적**

### 디렉터리 / 파일 / 클러스터 / 섹터 관계
```
File System
   └ lists a → Filename ─ stored in → Directory
                  └ maps to → Cluster chain ─ stored in → File Allocation Table(FAT)
                                 └ maps to → Logical sectors ─ map to → Physical sectors
```

### 클러스터 (Cluster)
- **파일이 사용하는 공간의 최소 단위**.
- 하나 이상의 **인접 섹터**로 구성. 크기는 **파일 시스템 종류 + 파티션 크기**에 따라 결정.
- 파일 = **클러스터의 연결된 시퀀스(linked sequence)**.
- 파일은 **항상 최소 1개 클러스터**를 사용 → **공간 낭비(internal fragmentation)** 발생 가능.

> 💡 **예제**: 8,200바이트 파일 + 4KB 클러스터 → **3개 클러스터** 필요.
> Cluster1(4096 사용) + Cluster2(4096) + Cluster3(8바이트만 사용, **4,088바이트 낭비**). → [[15장_강조포인트]]

## 3. FAT (File Allocation Table)

- 디스크의 **모든 클러스터 지도**. 각 클러스터가 어느 파일 소유인지 표시.
- **각 엔트리 = 한 클러스터 번호**에 대응. 각 클러스터는 1개 이상 섹터.
- 각 파일은 FAT 안에서 **연결 리스트(linked list) = 클러스터 체인(cluster chain)** 으로 표현.
- **각 엔트리는 n비트 정수**로 **다음 엔트리(클러스터)** 를 가리킴.

### FAT 종류 (엔트리 비트 길이로 명명)
| 종류 | 엔트리 크기 |
|------|-------------|
| **FAT-12** | 12비트 |
| **FAT-16** | 16비트 |
| **FAT-32** | 32비트 |

### 클러스터 체인 예
```
File1: 시작 클러스터 1, 크기 7 클러스터
엔트리: 1→2, 2→3, 3→4, 4→8, 8→9, 9→10, 10→eof
        (체인: 1,2,3,4,8,9,10)

File2: 시작 클러스터 5, 크기 5 클러스터
엔트리: 5→6, 6→7, 7→11, 11→12, 12→eof
        (체인: 5,6,7,11,12)
```
> 🔑 FAT 엔트리는 **"이 클러스터 다음은 몇 번 클러스터"** 를 저장. `eof`(end-of-file) 마커로 체인 종료. → [[15장_시험노트]]

## 4. 디스크 섹터 읽기/쓰기 — INT 21h 7305h

- **INT 21h, 기능 7305h** = 절대 디스크 읽기/쓰기(absolute disk read/write).
- **논리 디스크 섹터**를 직접 읽고 씀.
- **16비트 실주소 모드에서만 동작**. Windows 2000/XP/Vista/7에서는 **동작 안 함**(보안 강화).

### DISKIO 구조체 (7305h가 사용)
```asm
DISKIO STRUCT
    startSector DWORD 0       ; 시작 섹터 번호
    numSectors  WORD  1       ; 섹터 개수
    bufferOfs   WORD  buffer  ; 버퍼 오프셋
    bufferSeg   WORD  @DATA   ; 버퍼 세그먼트
DISKIO ENDS
```
### 예제 — 드라이브 C에서 섹터 읽기
```asm
.data
buffer     BYTE 512 DUP(?)
diskStruct DISKIO <>
.code
mov ax, 7305h              ; 절대 R/W
mov cx, 0FFFFh             ; 항상 이 값
mov dl, 3                  ; 드라이브 C (1=A,2=B,3=C…)
mov bx, OFFSET diskStruct
mov si, 0                  ; 0 = 읽기 (1=쓰기)
int 21h
```

## 5. 시스템 수준 파일 함수 (System-Level File Functions)

### 자주 쓰는 디스크 관련 INT 21h 함수
| 기능번호 | 기능 |
|----------|------|
| 0Eh | Set default drive |
| 19h | Get default drive |
| 7303h | Get disk free space |
| **39h** | Create subdirectory |
| **3Ah** | Remove subdirectory |
| 3Bh | Set current directory |
| 41h | Delete file |
| 43h | Get/set file attribute |
| 47h | Get current directory path |
| 4Eh | Find first matching file |
| 4Fh | Find next matching file |
| 56h | Rename file |
| 57h | Get/set file date and time |
| 59h | Get extended error information |

### 예제 — 서브디렉터리 생성 (39h)
```asm
.data
pathname BYTE "\ASM",0
.code
mov ah, 39h
mov dx, OFFSET pathname
int 21h
jc  DisplayError           ; CF=1이면 실패
```
### 예제 — 서브디렉터리 삭제 (3Ah)
```asm
.data
pathname BYTE 'C:\ASM',0
.code
mov ah, 3Ah
mov dx, OFFSET pathname
int 21h
jc  DisplayError
```
> ⚠️ 시스템 수준 파일 함수도 공통적으로 **실패 시 CF=1** → `jc`로 처리. 경로명은 **null(`,0`) 종료**.

## 6. 한 줄 요약
- **물리 구조**: 트랙(동심원)·섹터(트랙 조각)·실린더(한 헤드 위치 트랙들)·seek.
- **단편화**: 섹터가 비연속 → 느림.
- **클러스터**: 파일의 최소 할당 단위(인접 섹터). 항상 ≥1 클러스터 → 낭비 가능.
- **FAT**: 클러스터 지도, 파일 = 클러스터 체인(연결 리스트). FAT-12/16/32.
- **7305h**: 섹터 직접 R/W(16비트 전용, 최신 Windows 차단).
- **시스템 파일 함수**: 39h 생성/3Ah 삭제 등, 실패는 CF=1.
