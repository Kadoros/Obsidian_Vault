# 15장 디스크 기초 — 시험노트 📝

> 용어 구분(트랙/실린더/섹터/클러스터) + 클러스터 수 계산 + FAT 체인 추적이 출제 핵심.

## ❗ 함정
1. **트랙 vs 실린더**: 트랙은 한 면의 동심원 하나, 실린더는 **여러 플래터의 같은 반지름 트랙 묶음**(한 헤드 위치).
2. **섹터 vs 클러스터**: 섹터는 물리 단위(512B), 클러스터는 **파일 할당 단위**(섹터 여러 개). 파일은 클러스터 단위로만 할당됨.
3. **클러스터 수는 올림(ceil)**: 파일이 1바이트라도 넘으면 클러스터 하나 더. 마지막 클러스터의 남는 공간은 낭비.
4. **FAT 엔트리는 "다음 클러스터 번호"**, 데이터 자체가 아님. 마지막은 eof.
5. **7305h는 16비트 전용** → 최신 Windows에서 안 됨(보안). 서술형 단골.
6. **시스템 함수 실패는 CF** (`jc`), AX 아님. 경로명 null 종료 필수.

## 🧮 클러스터 수 계산 절차
`필요 클러스터 = ceil(파일크기 / 클러스터크기)`, 낭비 = `클러스터수×클러스터크기 − 파일크기`.
- 예: 10,000B / 4KB → ceil(2.44) = **3 클러스터**, 낭비 = 12,288 − 10,000 = **2,288B**.

## 📐 FAT 클러스터 체인 추적
시작 클러스터부터 엔트리를 따라가며 eof까지. 
- File1 시작=1: 1→2→3→4→8→9→10→eof ⇒ 7클러스터.
- File2 시작=5: 5→6→7→11→12→eof ⇒ 5클러스터.

## 📊 비교: FAT 종류
| 종류 | 엔트리 | 특징 |
|------|--------|------|
| FAT-12 | 12bit | 소형(플로피) |
| FAT-16 | 16bit | 중형 |
| FAT-32 | 32bit | 대용량 |

## 💬 서술형 대비
- **단편화가 성능을 떨어뜨리는 이유**: 파일 섹터가 비연속이라 헤드가 여러 트랙을 오가며(seek) 읽어야 해서 느림.
- **클러스터가 공간을 낭비하는 이유**: 파일은 최소 1클러스터 단위로 할당되므로, 작은 파일도 클러스터 하나를 통째 차지, 마지막 클러스터의 잔여 공간 낭비(internal fragmentation).
- **FAT의 역할**: 디스크 모든 클러스터의 소유/연결을 기록, 파일을 클러스터 체인(연결 리스트)으로 표현.
- **7305h가 최신 Windows에서 막힌 이유**: 응용 프로그램의 직접 디스크 섹터 접근은 보안상 위험하므로 보호 모드 OS가 차단.
