# 08장 고급 프로시저 — 시험노트 📝

> 스택 프레임 다이어그램 그리기 + 오프셋 계산이 핵심 출제 유형.

## ❗ 함정
1. **파라미터 오프셋 순서**: 먼저 push한 인수가 **더 높은 주소(+큰 오프셋)**.
   - `push val2; push val1; call` → val1 = `[ebp+8]`, val2 = `[ebp+12]`.
   - 즉 **마지막에 push한 인수가 [ebp+8]**.
2. **[ebp+4]는 항상 복귀 주소.** 파라미터는 +8부터.
3. **OFFSET으로 지역변수 주소 못 구함** → LEA 사용. (런타임 주소이므로)
4. **`ret n`의 n은 바이트 단위**. DWORD 인수 2개면 `ret 8`.
5. **EBP 복원 누락**하면 호출자 프레임 깨짐 → 반드시 `pop ebp`.
6. **C규약은 호출자가 add esp**, stdcall은 ret n. 둘 다 하면 이중 정리(버그).

## 🧮 오프셋 계산 절차
1. `push ebp; mov ebp,esp` 가정.
2. `[ebp]`=저장EBP, `[ebp+4]`=복귀, `[ebp+8]`=첫 인수(맨 마지막 push), 이후 +4씩.
3. 지역변수는 선언 순서대로 `[ebp-4]`, `[ebp-8]`...

## 📐 비교: ENTER/LEAVE vs 수동
| | 수동 | ENTER/LEAVE |
|---|---|---|
| 진입 | push ebp; mov ebp,esp; sub esp,n | `enter n,0` |
| 종료 | mov esp,ebp; pop ebp | `leave` |

## 📊 비교: 값 vs 참조 전달
| | push 대상 | 프로시저 안 | 원본 변경 |
|---|---|---|---|
| 값 | 변수 값 | 사본 사용 | 불가 |
| 참조 | OFFSET(주소) | 주소로 역참조 | **가능** |

## 💬 서술형 대비
- **스택 프레임이란?** = activation record. 복귀주소·파라미터·저장 레지스터·지역변수를 담는 스택 영역.
- **EBP를 쓰는 이유**: ESP는 push/pop으로 계속 변하므로, 고정된 기준점(EBP)으로 `[ebp±n]` 접근.
- **재귀가 스택을 소비하는 이유**: 호출마다 새 프레임(파라미터+복귀주소+EBP)을 쌓기 때문. 깊이 제한 없으면 스택 오버플로.
- **USES의 장점**: 저장/복원 코드를 자동 생성해 실수 방지.
