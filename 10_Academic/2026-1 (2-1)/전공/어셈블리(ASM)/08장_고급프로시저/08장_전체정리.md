## 1. 스택 프레임 (Stack Frame = Activation Record, 활성 레코드)

프로시저의 **복귀 주소 + 전달 파라미터 + 저장된 레지스터 + 지역변수**를 위해 스택에 마련된 영역. 만들어지는 순서:

1. **호출 프로그램**이 인수(arguments)를 스택에 **push**하고 프로시저를 `call`.
2. **호출된 프로시저**가 `push ebp` → `mov ebp, esp` (EBP를 프레임 기준점으로).
3. 지역변수가 필요하면 **ESP에서 상수를 빼서**(`sub esp, n`) 공간 확보.

### 표준 프레임 구조 (32비트, push ebp / mov ebp,esp 직후)
```
높은 주소 ↑
   [ebp+12]  두 번째 인수
   [ebp+8]   첫 번째 인수
   [ebp+4]   복귀 주소(return address)
   [ebp]     저장된 EBP        ← EBP가 여기를 가리킴
   [ebp-4]   지역변수 1
   [ebp-8]   지역변수 2
낮은 주소 ↓ ← ESP
```

> 🔑 **EBP = base pointer = frame pointer**. 프레임의 기준 주소를 담는다.
> - 함수 실행 중 EBP는 **변하지 않는다**.
> - 함수 복귀 시 EBP는 **원래 값으로 복원**되어야 한다(`pop ebp`).
> - 파라미터는 `[ebp+양수]`, 지역변수는 `[ebp-양수]`. → [[08장_강조포인트]]

## 2. 스택 파라미터 (Stack Parameters)

레지스터 파라미터보다 **편리**(개수 제한 없음). 두 방식:

### 2-1. 값으로 전달 (Pass by Value)
인수의 **값**을 push.
```asm
.data
val1 DWORD 5
val2 DWORD 6
.code
push val2          ; 6
push val1          ; 5   ← ESP (CALL 직전)
call ...
```

### 2-2. 참조로 전달 (Pass by Reference)
인수의 **오프셋(주소)**을 push.
```asm
push OFFSET val2   ; 00000004
push OFFSET val1   ; 00000000  ← ESP
call ...
```
CALL 후 스택(위→아래): `value/addr of val2`, `value/addr of val1`, `return address ← ESP`.

### 2-3. 누가 스택에서 파라미터를 제거하나? (Calling Convention)
| 규약 | 정리 주체 | 방법 |
|------|-----------|------|
| **C 규약** | **호출자(caller)** | call 후 `add esp, n` |
| **STDCALL** | **피호출 프로시저** | `ret n` (EIP 복원 후 ESP에 n 더함) |

```asm
; C 규약 (호출자가 정리)        ; STDCALL (피호출자가 정리)
push val2                       AddTwo PROC
push val1                           push ebp
call AddTwo                         mov  ebp, esp
add  esp, 8     ← 호출자 정리       mov  eax, [ebp+12]
                                    add  eax, [ebp+8]
                                    pop  ebp
                                    ret  8    ← 피호출자 정리
```
> `ret n`: EIP에 복귀주소 대입 **후** ESP에 n바이트를 더해 파라미터 제거.

### 2-4. 배열을 참조로 전달
```asm
.data
count = 100
array WORD count DUP(?)
.code
    push OFFSET array
    push COUNT
    call ArrayFill
```
```asm
ArrayFill PROC
    push ebp
    mov  ebp, esp
    pushad
    mov  esi, [ebp+12]   ; offset(array)
    mov  ecx, [ebp+8]    ; count
    ...
```
> ESI가 배열 시작을 가리키므로 이름을 몰라도 루프로 접근 가능.

## 3. 레지스터 저장 / 복원

프로시저 내부에서 망가뜨릴 레지스터는 **EBP 설정 직후 push**, 끝에서 역순 pop.
```asm
MySub PROC
    push ebp
    mov  ebp, esp
    push ecx          ; 지역 레지스터 저장
    push edx
    ...
```
### USES 연산자 — 저장/복원 코드 자동 생성
```asm
MySub1 PROC USES ecx edx
    ret
MySub1 ENDP
```
→ MASM이 자동으로:
```asm
MySub1 PROC
    push ecx
    push edx
    ...
    pop  edx
    pop  ecx
    ret
```

## 4. 지역변수 (Local Variables)

- 서브루틴 **내부 코드만** 보거나 수정 가능.
- 서브루틴 종료 시 **저장공간 해제**(스택 회수).
- 다른 함수의 지역변수와 **이름 충돌 없음**.

### 수동 생성 (ESP를 내려 공간 확보)
```asm
MySub PROC
    push ebp
    mov  ebp, esp
    sub  esp, 8                  ; DWORD 2개 공간
    mov  DWORD PTR [ebp-4], 10   ; x = 10
    mov  DWORD PTR [ebp-8], 20   ; y = 20
```

## 5. LEA 명령어 (Load Effective Address)

- **LEA**는 직접·간접 피연산자의 **오프셋을 반환**.
- **OFFSET 연산자는 상수 오프셋만** 반환 가능 → 스택 파라미터·지역변수의 주소는 OFFSET으로 못 구함.
```asm
mov esi, OFFSET [ebp-8]   ; ❌ 에러
lea esi, [ebp-8]          ; ✔ OK — 지역변수의 실제 주소
```
```asm
CopyString PROC, count:DWORD
    LOCAL temp[20]:BYTE
    mov edi, OFFSET count    ; ❌ invalid
    lea edi, count           ; ✔
    lea esi, temp            ; ✔
```
> 🔑 **스택 파라미터·지역변수 주소 = LEA 필수** (런타임 주소이므로). → [[08장_시험노트]]

## 6. ENTER / LEAVE 명령어

### ENTER — 스택 프레임 생성
```asm
MySub PROC
    enter 8, 0
```
`enter 8,0` ≡
```asm
push ebp
mov  ebp, esp
sub  esp, 8        ; 지역변수 8바이트
```
(첫 피연산자 = 지역변수 바이트 수, 둘째 = 렉시컬 중첩 레벨 보통 0)

### LEAVE — 스택 프레임 해제
```asm
leave   ≡   mov esp, ebp   ; 지역공간 해제
            pop ebp
```
```asm
MySub PROC
    enter 8, 0
    ...
    leave
    ret
MySub ENDP
```

## 7. LOCAL 지시어

- 지역변수 목록을 선언. **PROC 지시어 바로 다음 줄**에 위치. 각 변수에 타입 지정.
```asm
MySub PROC
    LOCAL var1:BYTE, var2:WORD, var3:SDWORD
```
```asm
LOCAL flagVals[20]:BYTE      ; 바이트 배열
LOCAL pArray:PTR WORD        ; 워드 배열 포인터
```
**BubbleSort 예 — MASM이 생성하는 코드:**
```asm
BubbleSort PROC
    LOCAL temp:DWORD, SwapFlag:BYTE
    ; ↓ MASM 생성
    push ebp
    mov  ebp, esp
    add  esp, 0FFFFFFF8h    ; = ESP에 -8 (DWORD+BYTE 정렬→8바이트)
    ...
    mov  esp, ebp
    pop  ebp
    ret
```
스택 프레임: `return address / EBP(←EBP) / temp[ebp-4] / SwapFlag[ebp-8](←ESP)`.

> 💡 `add esp, 0FFFFFFF8h`는 `sub esp, 8`과 동일(2의 보수). 지역변수는 정렬되어 할당.

## 8. 재귀 (Recursion)

- **정의**: 프로시저가 **자기 자신을 호출**하거나, A→B→A 형태로 호출. 호출 그래프에서 **사이클(cycle)** 을 형성.
- 각 호출마다 **새 스택 프레임**(파라미터·복귀주소·EBP)이 쌓인다 → 호출 깊이만큼 스택 소비.

### 예 1: CalcSum (배열 합, ECX=개수 → EAX=합)
```asm
CalcSum PROC
    cmp ecx, 0          ; 카운터 검사
    jz  L2              ; 0이면 종료 (base case)
    add eax, ecx        ; 합에 더함
    dec ecx
    call CalcSum        ; 재귀 호출
L2: ret
CalcSum ENDP
```
ECX=5: 5+4+3+2+1 = 15.

### 예 2: 팩토리얼
```
int factorial(int n) {
    if(n == 0) return 1;            // base case
    else return n * factorial(n-1);
}
```
```asm
Factorial PROC
    push ebp
    mov  ebp, esp
    mov  eax, [ebp+8]        ; n
    cmp  eax, 0
    ja   L1
    mov  eax, 1              ; n==0 → 1 반환
    jmp  L2
L1: dec  eax
    push eax                 ; Factorial(n-1)
    call Factorial
ReturnFact:                  ; 재귀 복귀 후 실행
    mov  ebx, [ebp+8]        ; n
    mul  ebx                 ; eax = eax * n
L2: pop  ebp
    ret  4                   ; 스택 정리 (파라미터 4바이트)
Factorial ENDP
```
> ⚠️ **재귀 동작 두 단계**: ① 내려가며 호출 쌓기(recursive calls) → ② 베이스에서 되돌아오며 곱셈(backing up). 5! = 5·4·3·2·1·1 = 120.
> 12! 계산 시 각 재귀 호출이 **12바이트**(n 4 + ReturnFact 4 + EBP 4) 스택 사용. → [[08장_예상문제]]

## 9. INVOKE / ADDR / PROC / PROTO

### INVOKE 지시어
- 32비트 모드에서 Intel `CALL`을 대체하는 강력한 지시어. **여러 인수**를 한 번에 전달.
```
INVOKE procedureName [, argumentList]
```
인수로 가능: 즉시값·정수식, 변수명, 주소/ADDR식, 레지스터명.
```asm
.data
byteVal BYTE 10
wordVal WORD 1000h
.code
INVOKE Sub1, byteVal, wordVal     ; 직접 피연산자
INVOKE Sub2, ADDR byteVal         ; 변수의 주소
INVOKE Sub3, eax, (10 * 20)       ; 레지스터, 정수식
INVOKE Sub4, [ebx]                ; 주소식(간접)
```

### PROC 지시어 (이름 있는 파라미터)
```
label PROC paramList            ; paramName : type
```
```asm
AddTwo PROC,
    val1:DWORD, val2:DWORD
    mov eax, val1
    add eax, val2
    ret
AddTwo ENDP
```
타입은 표준 ASM 타입(BYTE, SBYTE, WORD…) 또는 그 포인터. 파라미터를 여러 줄로 쓸 땐 `label PROC,` 뒤에 **콤마 필수**.
```asm
FillArray PROC,
    pArray:PTR BYTE, fillVal:BYTE,
    arraySize:DWORD
    mov ecx, arraySize
    mov esi, pArray
    mov al, fillVal
L1: mov [esi], al
    inc esi
    loop L1
    ret
FillArray ENDP
```
> **PROTO** 지시어로 프로시저의 프로토타입(시그니처)을 선언해야 INVOKE가 인수 타입을 검사할 수 있다(다중모듈/전방참조 시 필요).

## 10. 한 줄 요약 (Summary)
- **스택 파라미터**: 레지스터보다 편리. 값/참조 전달. ENTER/LEAVE로 프레임 관리.
- **지역변수**: 스택 포인터 아래에 생성. LOCAL 지시어.
- **재귀**: 프로시저가 자신을 호출, 각 호출이 새 프레임 사용.
- **호출 규약**: C(호출자 정리) vs stdcall(피호출자 정리).
- **MASM 프로시저 지시어**: INVOKE, PROC, PROTO.
