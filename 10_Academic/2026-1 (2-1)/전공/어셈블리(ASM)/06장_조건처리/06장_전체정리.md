# 06장 조건 처리 (Conditional Processing) — 전체정리

> 출처: Irvine, *Assembly Language for x86 Processors* 7/e, Ch.6
> 핵심: **CMP/논리 연산으로 플래그를 세팅 → 조건부 점프/루프로 분기** 한다. 고급 언어의 IF / WHILE / AND·OR / switch 를 어셈블리로 어떻게 번역하는가가 이 장의 전부다.

---

## 0. 이 장의 큰 그림

고급 언어(C/Java)의 제어 흐름은 어셈블리에서 다음 두 단계로 구현된다.

1. **상태(플래그)를 만든다** — `CMP`, `AND`, `OR`, `XOR`, `TEST` 등이 **상태 플래그(ZF, CF, SF, OF, PF)** 를 세팅한다.
2. **플래그를 보고 분기한다** — `Jcond`(조건부 점프), `LOOPcond`(조건부 루프)가 플래그를 검사해 점프한다.

이 "**플래그 세팅 → 플래그 검사 분기**" 패턴이 6장 전체를 관통하는 단 하나의 아이디어다.

---

## 1. 불리언 / 비트 단위 명령어 (Boolean & Bitwise)

개별 비트를 조작하며, 동시에 **상태 플래그를 세팅**한다.

| 명령어 | 동작 | 주 용도 |
|--------|------|---------|
| `AND dest, src` | 비트 AND | 특정 비트 **끄기(clear)** — 마스크의 0인 자리 제거 |
| `OR dest, src` | 비트 OR | 특정 비트 **켜기(set)** |
| `XOR dest, src` | 비트 XOR | 특정 비트 **토글**, 레지스터 0으로 초기화(`xor eax,eax`) |
| `NOT dest` | 1의 보수 | 모든 비트 반전 |
| `TEST dest, src` | AND 하되 **결과를 버림** | 특정 비트가 켜졌는지 **검사만** (피연산자 보존) |

- `AND`/`OR`/`XOR`/`TEST`는 **CF=0, OF=0**으로 만들고 SF, ZF, PF를 결과에 따라 세팅한다.
- 대문자/소문자 변환 트릭: 문자 비트 5번을 `AND`로 끄면 대문자, `OR 20h`로 켜면 소문자.
- **`TEST`**: 결과를 저장하지 않고 ZF만 본다. `test al, 1` → 최하위 비트(홀짝) 검사. → [[06장_강조포인트]]

---

## 2. CMP 명령어

```asm
CMP dest, src    ; dest - src 를 (가상으로) 수행하여 플래그만 세팅, dest는 변하지 않음
```

`CMP`는 **암묵적 뺄셈(implied subtraction)** 이다. 결과를 저장하지 않고 플래그만 바꾼다.

| 비교 | 플래그 결과 |
|------|-------------|
| dest = src | ZF = 1 |
| dest > src (부호 없음) | ZF = 0, CF = 0 |
| dest < src (부호 없음) | CF = 1 |

부호 있는 비교는 SF, OF, ZF의 조합으로 판단한다 (아래 점프 표 참고).

---

## 3. 조건부 점프 (Conditional Jumps)

`CMP` 직후 사용하며, 네 부류로 외운다.

**(1) 동등 비교**

| 점프 | 조건 |
|------|------|
| `JE` / `JZ` | ZF=1 (같음) |
| `JNE` / `JNZ` | ZF=0 (다름) |

**(2) 부호 없는 정수 (Above/Below)**

| 점프 | 조건 | 의미 |
|------|------|------|
| `JA` / `JNBE` | CF=0 and ZF=0 | dest > src |
| `JAE` / `JNB` | CF=0 | dest ≥ src |
| `JB` / `JNAE` | CF=1 | dest < src |
| `JBE` / `JNA` | CF=1 or ZF=1 | dest ≤ src |

**(3) 부호 있는 정수 (Greater/Less)**

| 점프 | 조건 | 의미 |
|------|------|------|
| `JG` / `JNLE` | SF=OF and ZF=0 | dest > src |
| `JGE` / `JNL` | SF=OF | dest ≥ src |
| `JL` / `JNGE` | SF≠OF | dest < src |
| `JLE` / `JNG` | SF≠OF or ZF=1 | dest ≤ src |

**(4) 특정 플래그**: `JC`(CF=1), `JNC`, `JZ`, `JNZ`, `JO`(OF), `JS`(SF), `JP`(PF) 등.

> ⚠️ **시험 단골 함정**: 부호 없음은 **A/B**(Above/Below), 부호 있음은 **G/L**(Greater/Less). 잘못 쓰면 음수 비교가 깨진다. → [[06장_시험노트]]

## 4. 조건부 루프 명령어 (Conditional Loop Instructions)

`LOOP`처럼 **ECX를 감소**시키되, 추가로 **ZF**를 함께 본다.

### LOOPZ / LOOPE (Loop while Zero / Equal)
```
LOOPE destination
LOOPZ destination
```
동작:
1. `ECX ← ECX − 1`
2. **ECX > 0 AND ZF = 1** 이면 destination으로 점프

→ 배열에서 주어진 값과 **일치하지 않는 첫 원소**를 찾을 때 유용 (같은 동안 계속 돈다).

### LOOPNZ / LOOPNE (Loop while Not Zero / Not Equal)
```
LOOPNZ destination
LOOPNE destination
```
동작:
1. `ECX ← ECX − 1`
2. **ECX > 0 AND ZF = 0** 이면 destination으로 점프

→ 배열에서 주어진 값과 **일치하는 첫 원소**를 찾을 때 유용.

**LOOPNZ 예제 — 배열의 첫 양수 찾기**
```asm
.data
array  SWORD -3,-6,-1,-10,10,30,40,4
sentinel SWORD 0
.code
    mov esi, OFFSET array
    mov ecx, LENGTHOF array
next:
    test WORD PTR [esi], 8000h   ; 부호 비트 검사 (음수면 ZF=0)
    pushfd                       ; loopnz 전에 플래그 보존
    add esi, TYPE array
    popfd                        ; 플래그 복원
    loopnz next                  ; 음수인 동안(ZF=0) 계속
    jnz quit                     ; 못 찾음
    sub esi, TYPE array          ; ESI가 찾은 값을 가리키게 되돌림
quit:
```
> 💡 `test`/`cmp`가 세팅한 ZF를 `add esi` 같은 명령이 망가뜨리므로 **`pushfd`/`popfd`로 플래그를 보존**하는 패턴이 핵심. → [[06장_예상문제]]

## 5. 조건 구조 (Conditional Structures)

### 5-1. 블록 구조 IF 문
C++/Java의 `if/else`를 `CMP`+`Jcond`로 번역한다.
```
if( op1 == op2 )           mov eax, op1
   X = 1;                   cmp eax, op2
else            →           jne L1
   X = 2;                   mov X, 1
                            jmp L2
                        L1: mov X, 2
                        L2:
```
패턴: **조건이 거짓일 때 건너뛸 곳으로 점프**, then-블록 끝에 `jmp`로 else를 건너뜀.

### 5-2. 복합 표현식 AND (단축 평가, short-circuit)
고급 언어는 **단축 평가**를 쓴다: 첫 조건이 거짓이면 둘째는 평가 안 함.
```
if (al > bl) AND (bl > cl)
   X = 1;
```
**효율적 구현 (fall-through, 코드 29% 절약)** — 관계 연산자를 **반대로 뒤집어** 거짓이면 즉시 탈출:
```asm
    cmp al, bl
    jbe next        ; 첫 조건 거짓 → 즉시 탈출
    cmp bl, cl
    jbe next        ; 둘째 조건 거짓 → 탈출
    mov X, 1        ; 둘 다 참
next:
```

### 5-3. 복합 표현식 OR (단축 평가)
첫 조건이 **참이면** 둘째는 건너뛴다.
```
if (al > bl) OR (bl > cl)
   X = 1;
```
```asm
    cmp al, bl
    ja  L1          ; 첫 조건 참 → 바로 실행으로
    cmp bl, cl
    jbe next        ; 둘째도 거짓 → 건너뜀
L1: mov X, 1
next:
```
> 🔑 **AND는 거짓이면 탈출(연산자 뒤집기), OR은 참이면 실행으로 점프**. 이 비대칭이 시험 포인트. → [[06장_강조포인트]]

### 5-4. WHILE 루프
WHILE = **IF + 본문 + 무조건 점프(맨 위로)**.
```
while( eax < ebx )
    eax = eax + 1;
```
```asm
top: cmp eax, ebx
     jae next       ; 조건 거짓 → 루프 탈출
     inc eax        ; 본문
     jmp top        ; 맨 위로
next:
```

### 5-5. 테이블 기반 선택 (Table-Driven Selection)
다중 분기(switch/case)를 **테이블 룩업**으로 대체. 비교 대상이 많을 때 유리.

**Step 1 — 룩업 값 + 프로시저 주소 테이블 구성**
```asm
.data
CaseTable BYTE 'A'                 ; 룩업 값
          DWORD Process_A          ; 프로시저 주소
          EntrySize = ($ - CaseTable)
          BYTE 'B'
          DWORD Process_B
          BYTE 'C'
          DWORD Process_C
          BYTE 'D'
          DWORD Process_D
NumberOfEntries = ($ - CaseTable) / EntrySize
```
**Step 2 — 루프로 테이블 탐색, 일치 시 저장된 주소 호출**
```asm
    mov ebx, OFFSET CaseTable
    mov ecx, NumberOfEntries
L1: cmp al, [ebx]                  ; 일치?
    jne L2
    call NEAR PTR [ebx + 1]        ; 프로시저 포인터 호출 (NEAR PTR 필수)
    call WriteString
    call Crlf
    jmp L3
L2: add ebx, EntrySize             ; 다음 엔트리
    loop L1
L3:
```
> 장점: 비교 개수가 늘어도 코드가 길어지지 않고 **테이블에 한 줄만 추가**하면 된다.

## 6. 응용: 유한 상태 기계 (Finite-State Machine, FSM)

- **FSM** = 입력에 따라 상태가 바뀌는 **그래프(상태 전이도, state-transition diagram)**.
- 노드(squares/circles) = 상태, 엣지(arrows) = 입력에 따른 전이.
- 방향 그래프(directed graph)의 한 사례. 세 종류 상태:
  - **Start state** (시작)
  - **Terminal state(s)** (수락/종료 — 이중 테두리)
  - **Nonterminal state(s)** (중간)
- **수락(accept)**: 입력 기호열이 최종 상태로 끝나면 그 문자열을 수락. → 정규 표현식(언어 규칙) 검증에 사용.
- 장점: 흐름을 **시각적으로 추적**, 수정 용이, 어셈블리로 구현 쉬움.

**예: 부호 있는 정수를 인식하는 FSM**
- State A(시작): `+`/`-` → State B / 숫자 → State C
- State B: 숫자 → State C (부호 뒤엔 반드시 숫자)
- State C(수락): 숫자 → State C 유지 / Enter → 종료

**구현 핵심 (Finite.asm)** — 각 상태를 레이블로, 전이를 `cmp`+`je`로:
```asm
StateA:
    call Getnext            ; 다음 문자 → AL
    cmp al, '+'
    je  StateB
    cmp al, '-'
    je  StateB
    call IsDigit            ; 숫자면 ZF=1
    jz  StateC
    call DisplayErrorMsg    ; 유효하지 않은 입력
    jmp Quit
```
> ⚠️ 잘못된 FSM 예: State A에서 부호 없이 바로 B로 가고 B에서 숫자를 받게 하면, **부호만 있고 숫자 없는 입력**(예: `+`)을 잘못 수락한다. 부호 뒤 숫자 강제가 핵심. → [[06장_예상문제]]

## 7. 한 줄 요약 (Summary)

- **비트 명령어**(AND/OR/XOR/NOT/TEST): 개별 비트 조작 + 플래그 세팅
- **CMP**: 암묵적 뺄셈으로 비교 플래그 세팅
- **조건부 점프/루프**: 동등(JE/JNE), 플래그(JC/JZ…), 부호 있음(JG/JL…), 부호 없음(JA/JB…), LOOPZ/LOOPNZ
- **순서도(flowchart)**: 논리 다이어그램 도구
- **FSM**: 런타임 상태 변화를 추적
