# 06장 조건 처리 — 시험노트 📝

> 헷갈리는 것 / 함정 / 자주 출제되는 비교 정리.

## ❗ 자주 틀리는 함정
1. **부호 vs 부호 없음 점프 혼동**
   - 음수가 섞인 비교에서 `JA/JB`(unsigned)를 쓰면 틀린다. → 부호 있으면 반드시 `JG/JL`.
   - `-1`은 unsigned로 `0FFFFFFFFh`(가장 큰 수)로 해석됨에 주의.
2. **CMP는 피연산자를 바꾸지 않는다.** 뺄셈처럼 보여도 dest 값은 그대로.
3. **LOOPZ vs LOOPNZ 방향**
   - 찾는 게 "일치하는 첫 원소" → `LOOPNZ`(다른 동안 돈다)
   - 찾는 게 "불일치하는 첫 원소" → `LOOPZ`(같은 동안 돈다)
   - ⇒ 이름과 직관이 반대처럼 느껴짐. "Z=계속 도는 조건"으로 외우기.
4. **조건부 루프 전 플래그 파괴**: `add esi, TYPE array`가 ZF를 바꿔서 `loopnz`가 잘못 동작 → `pushfd`/`popfd` 필요.
5. **AND vs OR 단축평가 구현 방향 반대**
   - AND: 거짓이면 탈출(`jbe next`)
   - OR: 참이면 실행 점프(`ja L1`)

## 📐 CMP 후 플래그 (부호 없음 기준)
| 관계 | ZF | CF |
|------|----|----|
| dest = src | 1 | 0 |
| dest > src | 0 | 0 |
| dest < src | 0 | 1 |

## 🧮 비교: 두 가지 AND 구현
| 방식 | 코드량 | 방법 |
|------|--------|------|
| 정직한 변환 | 김 | 각 조건 참이면 다음 레이블로 `ja`, 아니면 `jmp next` |
| fall-through | **29% 절약** | 연산자 뒤집어 거짓이면 즉시 `jbe next` |

## 🔁 비교: LOOP 계열
| 명령 | ECX 감소 | 추가 조건 | 점프 |
|------|----------|-----------|------|
| LOOP | ✔ | 없음 | ECX>0 |
| LOOPZ/LOOPE | ✔ | ZF=1 | ECX>0 and ZF=1 |
| LOOPNZ/LOOPNE | ✔ | ZF=0 | ECX>0 and ZF=0 |

## 💬 서술형 대비
- **"단축 평가(short-circuit evaluation)란?"**: 앞 조건만으로 결과가 확정되면 뒤 조건을 평가하지 않는 것. AND는 앞이 거짓이면, OR은 앞이 참이면 뒤를 생략.
- **"FSM이 부호 정수를 검증하는 원리"**: 시작 상태에서 부호/숫자를 받아 상태 전이, 숫자만 반복하다 Enter면 수락 상태로 종료. 부호 뒤 숫자 미존재 시 거부.
- **"테이블 기반 선택의 장점"**: 비교가 많아져도 코드 길이 불변, 테이블 엔트리만 추가.
