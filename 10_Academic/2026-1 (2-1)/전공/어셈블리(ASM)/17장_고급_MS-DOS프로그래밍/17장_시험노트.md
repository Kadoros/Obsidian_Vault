# 17장 인터럽트 처리 — 시험노트 📝

> IVT 오프셋 계산 + 35h/25h 구분 + 핸들러 작성 규칙 + No_Reset 로직이 출제 핵심.

## ❗ 함정
1. **IVT 오프셋 = INT번호 × 4** (각 엔트리 4바이트). 예: INT 9 → 9×4 = 36 = 24h.
2. **핸들러는 IRET로 복귀**(RET 아님), 그리고 **모든 레지스터 보존**.
3. **35h(얻기)는 ES:BX, 25h(설정)는 DS:DX**. 레지스터 쌍 혼동 주의.
4. **CLI를 길게 쓰면 시스템 타이머·키보드 멈춤** → 짧은 크리티컬 구간만.
5. **체이닝 누락**: 우리 핸들러만 실행하고 기존 핸들러로 점프 안 하면 정상 처리(키 입력 등)가 깨짐.
6. **벡터 교체 전 기존 주소를 35h로 저장**해야 체이닝과 복원이 가능.

## 🧮 IVT 오프셋 계산
`오프셋 = INT번호 × 4`.
- INT 8 → 32 = 20h, INT 10h(16) → 64 = 40h, INT 21h(33) → 132 = 84h.

## 📐 비교: 35h vs 25h
| | 35h | 25h |
|---|-----|-----|
| 동작 | 벡터 **얻기** | 벡터 **설정** |
| AL | INT 번호 | INT 번호 |
| 결과/입력 | ES:BX = 주소 반환 | DS:DX = 새 핸들러 |
| 용도 | 기존 핸들러 백업 | 새 핸들러 설치 |

## 📊 비교: STI vs CLI
| | STI | CLI |
|---|-----|-----|
| IF | 1 (활성) | 0 (비활성) |
| 위치 | 핸들러 시작 | 크리티컬 코드 직전 |
| 효과 | 외부 인터럽트 허용 | 인터럽트·타이머 정지 |

## 💬 서술형 대비
- **인터럽트 핸들러 작성 시 지켜야 할 규칙**: ① STI로 시작(인터럽트 허용), ② 사용하는 레지스터·플래그 모두 보존(push/pop), ③ IRET로 복귀, ④ 보통 기존 핸들러로 체이닝.
- **8259 PIC와 IRQ의 역할**: PIC가 하드웨어 신호를 받아 CPU에 인터럽트 전달, IRQ는 우선순위 기반으로 동시 요청을 중재(낮은 우선순위가 높은 것을 못 막음).
- **TSR이 키보드를 가로채는 원리**: INT 9 벡터를 자기 핸들러로 교체, 키 조합을 필터한 뒤 기존 INT 9 핸들러로 전방 체이닝해 정상 처리.
- **No_Reset이 리셋을 막는 방법**: Ctrl+Alt+Del 감지 시 Right Shift가 없으면 키보드 플래그의 Ctrl 비트를 꺼서 BIOS가 리셋 조합을 인식하지 못하게 함.

## 키보드 처리 7단계 (서술 빈출)
키 누름 → 8259가 CPU 인터럽트 → CPU가 IVT 9h 조회·분기 → 우리 핸들러 실행(가로채기) → 기존 INT 9로 점프 → INT 9h 완료·복귀 → 정상 처리 계속.
