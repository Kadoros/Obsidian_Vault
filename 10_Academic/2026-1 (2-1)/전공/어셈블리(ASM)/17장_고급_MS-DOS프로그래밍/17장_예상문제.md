# 17장 인터럽트 처리 — 예상문제 ✍️

## Q1. INT 9의 IVT 오프셋은? INT 21h는?
> **정답**: INT 9 → 9×4 = 36 = **24h**. INT 21h(=33) → 33×4 = 132 = **84h**.

## Q2. INT 9의 기존 핸들러 주소를 얻어 저장하는 코드?
> **정답**
> ```asm
> mov ah, 35h          ; 벡터 얻기
> mov al, 9            ; INT 9
> int 21h
> mov int9Save, bx     ; 오프셋
> mov [int9Save+2], es ; 세그먼트
> ```

## Q3. 새 키보드 핸들러 kybd_rtn을 INT 9에 설치하는 코드?
> **정답**
> ```asm
> mov ax, SEG kybd_rtn
> mov ds, ax
> mov dx, OFFSET kybd_rtn
> mov ah, 25h          ; 벡터 설정
> mov al, 9h           ; INT 9h
> int 21h
> ```

## Q4. 인터럽트 핸들러가 일반 프로시저와 다른 점 두 가지는?
> **정답**: ① 복귀 시 RET가 아니라 **IRET**를 사용(플래그도 함께 복원). ② 사용하는 **모든 레지스터·플래그를 보존**해야 함(인터럽트당한 프로그램 상태를 깨면 안 됨). (보통 시작에 STI, 끝에 기존 핸들러로 체이닝)

## Q5. STI와 CLI의 차이와 사용 시점은?
> **정답**: STI는 IF=1로 외부 인터럽트를 활성화(인터럽트 핸들러 시작에 사용). CLI는 IF=0으로 비활성화(인터럽트되면 안 되는 크리티컬 코드 직전에 사용, 시스템 타이머도 정지하므로 짧게).

## Q6. No_Reset에서 Ctrl+Alt+Del을 눌렀는데 Right Shift가 없을 때 리셋을 막는 방법은?
> **정답**: 키보드 플래그 바이트(0040:0017h)에서 **Ctrl 비트를 끈다**(`and ah, NOT ctrl_key`) 후 메모리에 다시 저장. BIOS가 Ctrl+Alt+Del 조합을 인식하지 못해 리셋이 일어나지 않고, 이어 기존 INT 9 핸들러로 체이닝한다.

## Q7. (서술) TSR 키보드 프로그램의 동작 원리를 설명하라.
> **정답**: 메모리에 상주하며 INT 9 벡터를 자신의 핸들러로 교체한다. 키가 눌리면 자기 핸들러가 먼저 실행되어 특정 키 조합을 검사·필터하고, 그 후 기존 INT 9 핸들러로 전방 체이닝(forward-chain)하여 정상적인 키보드 처리를 수행한다. 제거 프로그램이나 재부팅 전까지 메모리에 남는다.

## Q8. (서술) 키 누름부터 처리까지 7단계를 순서대로 설명하라.
> **정답**: ① 키 누름→바이트가 키보드 포트로. ② 8259 컨트롤러가 CPU를 인터럽트, 인터럽트 번호 전달. ③ CPU가 IVT 9h 엔트리 조회·분기. ④ 우리 핸들러 실행(바이트 가로채기). ⑤ 기존 INT 9 핸들러로 점프. ⑥ INT 9h 핸들러 완료·복귀. ⑦ 시스템 정상 처리 계속.
