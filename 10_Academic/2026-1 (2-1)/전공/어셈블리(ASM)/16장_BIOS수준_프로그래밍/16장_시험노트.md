# 16장 BIOS 수준 프로그래밍 — 시험노트 📝

> 속성 바이트 구성 + INT 16h/10h 기능번호 + 키보드 입력 흐름이 출제 핵심.

## ❗ 함정
1. **속성 바이트 = (배경 SHL 4) OR 전경**. 배경을 시프트 안 하고 그냥 OR하면 틀림.
2. **스캔 코드 ≠ ASCII 코드**: 같은 키도 Shift/Ctrl/Alt에 따라 스캔코드 다름. 화살표·F키는 ASCII 없음 → 스캔코드로만.
3. **INT 16h 11h는 키를 제거하지 않음**(확인만, ZF로). 실제 제거는 10h.
4. **BIOS vs MS-DOS vs 직접 메모리매핑** 속도/호환성 순서 혼동 주의: 직접매핑이 가장 빠르나 IBM 100% 호환만.
5. **DX=184Fh 해석**: DH=24(행), DL=79(열). 행은 0-24, 열은 0-79.
6. BIOS 데이터 영역(0040:0017h)은 Windows NT/2000/XP에서 접근 불가.

## 🧮 속성 바이트 계산 절차
1. 전경색·배경색을 각각 0~15(4비트) 값으로.
2. `(배경 << 4) | 전경`.
- 예: 배경=파랑(1), 전경=흰색(15=Fh) → (1<<4)|15 = 10h|0Fh = **1Fh**.

## 📐 키 입력 흐름 (서술 빈출)
키스트로크 → 스캔코드가 직렬 포트로 → **INT 9h** ISR 실행 → 스캔코드+ASCII를 **typeahead 버퍼**에 삽입 → INT 16h(스캔+ASCII) 또는 INT 21h(ASCII만)가 읽음.

## 📊 비교: INT 16h 함수
| AH | 대기 | 버퍼에서 제거 | 반환 |
|----|------|---------------|------|
| 10h | O(블록) | O | AH=스캔, AL=ASCII |
| 11h | X | **X(확인만)** | ZF=0 키있음 |
| 12h | X | — | AX=플래그 |

## 📊 비교: INT 10h 출력
| AH | 출력 | 속성 |
|----|------|------|
| 09h | 문자+속성 | O |
| 0Ah | 문자만 | X |

## 💬 서술형 대비
- **BIOS가 MS-DOS보다 나은 점**: 그래픽·색상, 더 빠른 I/O, 마우스/포트 접근, 저수준 디스크.
- **typeahead 버퍼 역할**: 빠르게 친 키를 임시 저장해 프로그램이 나중에 읽도록.
- **속성 바이트 구조**: 상위 니블=배경, 하위 니블=전경(글자색), 전경 최상위는 intensity/blink.
- **Clrscr가 06h를 쓰는 이유**: 전체 윈도우를 빈 줄로 스크롤하면 화면이 비워지고, 이어 02h로 커서를 좌상단으로 옮김.
