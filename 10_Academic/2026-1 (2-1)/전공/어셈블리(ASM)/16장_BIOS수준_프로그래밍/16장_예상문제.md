# 16장 BIOS 수준 프로그래밍 — 예상문제 ✍️

## Q1. 키 하나를 대기하여 스캔코드와 ASCII를 저장하는 INT 16h 코드?
> **정답**
> ```asm
> mov ah, 10h
> int 16h
> mov scanCode, ah     ; 스캔 코드
> mov ASCIICode, al    ; ASCII 코드
> ```

## Q2. 파랑(1) 배경 + 흰색(Fh) 전경의 속성 바이트 값은?
> **정답**: (1 SHL 4) OR 0Fh = 10h | 0Fh = **1Fh**.

## Q3. 빨강(4) 배경 + 노랑(Eh) 전경의 속성 바이트는?
> **정답**: (4 SHL 4) OR 0Eh = 40h | 0Eh = **4Eh**.

## Q4. 키보드 입력 흐름(키 누름→프로그램이 읽기까지)을 순서대로 설명하라.
> **정답**: ① 키 누름 → 스캔코드가 키보드 직렬 입력 포트로 전송. ② 인터럽트 발생 → INT 9h 서비스 루틴 실행. ③ 스캔코드+ASCII가 typeahead 버퍼에 삽입. ④ INT 16h(스캔+ASCII) 또는 INT 21h(ASCII만)가 버퍼에서 읽음.

## Q5. INT 16h 함수 10h, 11h, 12h의 차이는?
> **정답**: 10h=키 대기(없으면 블록, 버퍼에서 제거, AH=스캔/AL=ASCII), 11h=버퍼 확인(대기X, 제거X, 키 있으면 ZF=0), 12h=키보드 상태 플래그 얻기(AX).

## Q6. 80×25 텍스트 화면 전체를 지우고 커서를 좌상단으로 옮기는 코드?
> **정답**
> ```asm
> mov ax, 0600h     ; 스크롤 업, 전체
> mov cx, 0         ; 좌상단 (0,0)
> mov dx, 184Fh     ; 우하단 (24,79)
> mov bh, 7         ; 일반 속성
> int 10h
> mov ah, 2         ; 커서 위치
> mov bh, 0
> mov dx, 0         ; (0,0)
> int 10h
> ```

## Q7. (서술) 스캔 코드와 ASCII 코드의 차이, 그리고 화살표 키가 문제가 되는 이유?
> **정답**: 스캔 코드는 어느 키가 눌렸는지(물리적 위치, Shift/Ctrl/Alt 조합 포함)를 나타내고, ASCII 코드는 그 문자의 표준 부호다. 화살표·F키 등은 대응 ASCII가 없으므로 ASCII 읽기로는 식별 불가, 스캔 코드로만 구분해야 한다(INT 21h로 읽으면 첫 읽기 0, 두 번째에 스캔코드).

## Q8. (서술) 비디오 접근 세 수준의 속도와 호환성을 비교하라.
> **정답**: MS-DOS 함수(느림, 모든 MS-DOS 머신), BIOS INT 10h(중간, 거의 모든 MS-DOS 기반), 직접 메모리매핑(가장 빠름, 100% IBM 호환 머신만).
